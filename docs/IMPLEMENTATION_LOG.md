## 31. 5차 실사용 감수: 과교정·오탐 8건 수정 (2026-07-26)

실제 대사 텍스트(사용자 제공)로 돌려 발견한 과교정/오탐을 근본 원인별로 수정. 모든 판별은 결정론적 신호(kiwi 형태소 태그 / `word_exists` / 반복구조 / 사전 뜻풀이 표지)만 쓰고 확률적 문맥 추측은 배제. 검증 근거는 `docs/HANDOFF_realusage_review.md`, 정답표 테스트는 `tests/test_realusage_review.py`(10건). 전체 스위트 108→ 통과, held-out eval 12/14 유지, `examples/sample.srt` 6건 자동교정 유지.

**A. 합성어 자동병합이 파스·문맥 무시** (`correct_compound_spacing`, 신규 `check_ambiguous_compound`, `dictionary.definition_markers`)
- '큰 애들'(크다 관형형 '큰'+'애들')을 준말 '큰애'로, '턱 밑'을 비유어 '턱밑'으로 자동 병합하던 과교정. 판별자는 표준국어대사전 뜻풀이의 '준말'/'비유적' 표지 — 이 표지가 있으면 붙임형이 띄어 쓴 구(句)와 의미가 경쟁하므로 자동 병합하지 않는다. 명사+명사(턱 밑)는 확인 플래그, 용언 관형사형+명사(큰 애들)는 명백한 구라 플래그도 안 함(사용자 확인). 함정: 용언 어간(크/VA)과 관형사형 어미(ㄴ/ETM)가 같은 `start`를 공유해 dict로는 덮어써지므로, 관형사형 판별은 `{t.start for VV/VA}` 집합으로. 회귀: 쓴맛/그때/노천카페(표지 없음) 자동 병합 유지.

**B. 모호한 자동교체 → 플래그**
- B1 '빤스'→'팬츠'(외래어 표기) 자동교체를, 된소리 구어형 '빤쓰'가 사전 표제어라 말투일 수 있으므로 플래그로 전환(`_tensified_headword_variant`로 한 음절 초성을 된소리로 바꾼 형태가 표제어인지 확인 → `correct_loanwords`·`correct_nonstandard_terms`에서 스킵, 미등록어 오탐도 억제, `check_colloquial_loanword`가 빤쓰/팬츠 선택 플래그). 회귀: 초코렛→초콜릿, 리모콘→리모컨(변이 표제어 없음) 자동교정 유지.
- B2 '백 배 나'의 '나'를 조사로 붙여 '백 배나'로 자동교정하던 것을, '낫다'의 활용 '나아'의 오기일 수 있어 플래그로(`_mechanical_respace`에서 행 끝 띄어쓴 '나'(JX)는 붙이지 않음, `check_ambiguous_particle`가 플래그). `check_spacing`과 중복 플래그는 `suggested_fix` 기준 dedup.

**C. 유효 표제어인데 미등록어/분리 오탐** (`check_spelling`의 `_unknown_content_words`, `check_spacing`의 `_protect_headword_run_splits`)
- C1 '얄짤없어': '얄짤'(NNG)+'없다'(VA)가 합쳐 표제어 '얄짤없다'면 미등록어 아님(인접 명사+용언 결합 확인).
- C2 '평생을 껄쩍지근하게 살았다': '껄쩍지근하다'(방언 표제어)를 '껄쩍 지근'으로 분리 제안하던 오탐 — 기존 사전 검사는 인접 두 토큰만 이어 봐서 놓침. 공백 삽입 지점을 포함하는 한글 런 전체를 사전과 대조(런 자체가 표제어이거나 용언이면 어간+다가 표제어면 되돌림).
- C3 '건숭건숭이야': '건숭'(방언 표제어) 첩어 반복이면 억제(`_is_reduplication`).
- C4 '콸콸콸': 같은 음절 반복(의성·의태어)이면 억제 — kiwi가 '콸'(NNP)+'콸콸'(MAG)로 쪼개 단독 '콸'만 남으므로 원문 음절 런(`_syllable_run_len`)으로 판별.
- C5 '김치찌갯집': 단독/반복 모두 현재 오탐 재현 안 됨(반복 등장 시 recurring-unknown 검출기가 NNP로 등록해 플래그 안 남). 별도 조치 불필요.

미해결/후속: `search_dialect()`(지역어 종합정보 API)는 현재 non-JSON을 반환해 사실상 중단 상태(assist 사투리 제안이 정적 convert 맵에만 의존). `docs/IMPLEMENTATION_LOG.md`가 30KB 임계를 넘어 다음 세션에 앞쪽 절반을 `docs/log-archive/`로 아카이브 필요. 리포트 UX(D: 긴 문장 변경 위치 표시)와 자막/일반 글 모드(E)는 미착수.

## 33. 6차 실사용 감수: 과교정·오탐 4건 수정 + 자막 마침표 재설계 (2026-07-26)

실제 자막 파일 감수에서 나온 사례. pytest 129 통과.

- **수강생(전 용어 오탐)**: '수강생'(수강+생/XSN, 표제어)에서 '수강'만 떼어 '골수 공간의 전 용어'로 플래그하던 오탐. correct_former_terms에서 명사 뒤 접미사(XSN)가 붙어 별개 표제어를 이루면 그 안의 명사를 옛 용어로 보지 않도록 가드 추가.
- **먹고 싶어 하는 → 싶어하는(근거 없는 결합 제안)**: _protect_unfounded_joining이 인접 두 토큰만(어+하다='어하다') 조회하는데 '어하다'라는 무관한 표제어와 우연히 겹쳐(집→지브 사고 동류) 근거 없는 결합을 정당한 것으로 오인. before가 연결어미(EC)면 어간까지 포함한 실제 용언(싶어+하다='싶어하다', 비표제어)으로 확인하도록 수정.
- **김치찌갯집(외래어 오탐)**: kiwi가 문맥에 따라 통짜 NNG로 태깅하면 '사전에 없는 단어: 외국어 음차'로 오탐. '김치'+'찌갯집' 둘 다 표제어인 고유어 합성어이므로 _is_native_compound(두 표제어 각 2글자+로 분해)면 미등록어에서 제외.
- **샘나(부당 분리)**: kiwi.space가 '샘 나'로 쪼개던 문제는 앞서 §32 이전 _protect_headword_run_splits(C2)로 이미 해결(샘나다 표제어 확인). 회귀 테스트만 추가.
- **자막 문장부호 재설계(E 보강)**: 기존엔 모든 문장 종결 마침표를 '제거 확인' 플래그로 냈으나, 사용자 요청에 따라 (1) 줄 끝 문장 종결 마침표는 정답이 하나뿐이라 자동 제거(correct_subtitle_final_period), (2) 한 줄에 두 문장이 이어질 때 문장 사이 마침표는 쉼표(,)로 바꾸자고 확인 플래그(check_subtitle_internal_period, 자동 아님)로 분리. 소수점·말줄임표 제외, 일반 글 모드는 구두점 유지.

## 34. 실사용 맞춤법 퀴즈 피드백 → 결정론적 규칙 도출 (2026-07-26)

사용자가 자막 대사 퀴즈로 교정 능력을 점검하고 정답을 알려줌. 17개 사례를 개별
패치가 아니라 일반 규칙으로 정리(docs/DESIGN_PRINCIPLES.md 워크플로 적용).

- **규칙 A 구현(자동 교정)**: 관형사(MM)·관형형(ETM) 뒤 '명사+하다'(NNG+하/XSV가
  붙은 어절)는 명사와 '하'를 띄운다 — 관형어는 명사를 꾸미므로 통사적 정답이
  하나뿐(문맥 무관). '뭔 생각하냐'→'뭔 생각 하냐', '만날 생각해'→'만날 생각 해'.
  `correct_adnominal_noun_verb_split()`. 제외: 부사 수식(잘 생각한다), 관형어가
  다른 명사 수식(그 사람 사랑한다), 이미 띄어진 경우, '하'가 독립동사(VV). 함정:
  '만날'은 문맥이 있어야 관형형으로 태깅되고 단독이면 부사('매일')로 태깅됨.
- **규칙 D(같이=처럼→조사 붙임) 자동화 불가**: kiwi가 '같이'를 처럼(조사)/함께
  (부사) 구분 없이 전부 MAG로 태깅. '처럼 대체' 판정은 의미 판단이라 결정론적
  자동이 불가능 → 플래그 영역(원리 2). 자동 교정하지 않는다.
- **규칙 B(감탄사·호격 쉼표 삽입) 실현 가능·미구현**: kiwi가 감탄사(IC: 아이고/뭐/
  거/응)와 호격조사(JKV: 준희+야)를 안정적으로 태깅하므로 결정론적 삽입이 가능.
  단 쉼표 배치는 기존 쉼표·나열·'거참'(한 단어 감탄사) 같은 예외가 많아 별도의
  신중한 구현이 필요(급하게 넣으면 과삽입 위험). 다음 작업으로 분리.
- **사실 정정**: 'X 하다' 판정 중 '뭐하다'가 사전에 없는 단어라고 오판했으나,
  '뭐하다'는 '거시기하다'(무엇을 하다) 뜻의 실재 표제어다. 그 뜻이 아닐 때만
  '뭐 해'로 띄운다.
- **의미 판단이 필요해 자동화하지 않고 플래그로 두는 사례**: 부딪히다(피동)/
  부딪치다(주어가 움직임), 잘살다(부자)/잘 살다(무탈), 봐주다(용서·도움)/봐 주다 —
  한 단어와 구가 뜻으로 갈리는 경우는 원리 2에 따라 자동 대신 사람 확인.

## 36. 띄어쓰기 기준 선택(원칙/허용) (2026-08-02)

사용자 요청: 웹 페이지에서 띄어쓰기를 원칙으로 할지 허용으로 할지 고를 수 있게 하되, **한 작품 안에 두 기준이 섞이면 안 된다**. 상세 설계는 `PRD.md` §13.

- **왜 필요했나**: 제47항의 원칙(띄어 씀)과 허용(붙여 씀)은 둘 다 맞는 표기다. 기존 엔진은 원칙만 지원해, 붙여 쓰기로 통일한 작품을 넣으면 전부 띄어 써 버렸다. 어느 쪽이 맞느냐가 아니라 **작품이 고르는 문제**라는 점이 핵심이다.
- **구조**: `correct_aux_verb_spacing`의 판정 로직을 `_aux_verb_spacing(text, mode)`로 옮기고, 기존 함수는 원칙 전용 얇은 래퍼로 남겼다(기존 호출부·테스트 8건이 그대로 통과). 대상 구간(패턴 1·2)은 두 기준이 완전히 동일하고, 간격을 넣느냐 빼느냐만 갈린다 — 그래서 탐지 로직을 복제하지 않고 `edits`에 치환 문자열(`" "` 또는 `""`)을 함께 담는 방식으로 한 곳에서 처리한다.
- **혼용 방지**: 기준은 `correct_entries(spacing_mode=...)`에서 한 번 정규화해 모든 줄에 같은 값을 넘긴다. 줄 단위로 다른 기준을 줄 수 있는 경로 자체를 만들지 않았다.
- **붙임 불가 구간**(본용언이 3음절 이상 합성어, 의존명사+하다 조합이 사전에 없음)은 허용 기준에서도 띄어 쓴다. 조용히 띄우면 사용자가 "허용을 골랐는데 왜 섞였지"로 오해하므로, 자동 교정 로그에 `[붙임 불가] ... -> 허용 기준에서도 띄어 씀` 사유를 남긴다(사용자 결정).
- **함정 1 — 안내문의 어절이 잘림**: 토큰 경계가 형태소 단위라 구간 텍스트를 그대로 쓰면 `'덤벼들어 보'`처럼 어절 중간에서 끊긴다. `_surface_span()`으로 양쪽 어절 경계까지 넓혀 `'덤벼들어 보아라'`로 보여준다.
- **함정 2 — 붙임 근거 확인 순서**: 패턴 2에서 원래 코드는 "일단 edits에 넣고 사전에 없으면 discard"였다. 허용 기준에서는 붙임 불가 **사유를 남겨야** 하므로 사전 확인을 먼저 하도록 순서를 바꿨다(원칙 기준의 결과는 동일).
- **노출**: `/api/correct`의 `spacing_mode` Form, `main.py --spacing principle|allowance`(모르는 값이면 원칙으로 진행한다고 알림), `static/index.html` 라디오 + "한 작품 안에서는 한쪽으로 통일" 안내 문구.
- **검증**: pytest 160건 통과(신규 10건). `examples/sample.srt` 두 기준 비교 결과 차이는 `할 만하다`/`할만하다` 한 줄뿐, 자동교정·플래그 3건은 동일. FastAPI `TestClient`로 `spacing_mode` 전달 확인(principle/allowance/알 수 없는 값 → 원칙). 허용 기준으로 붙인 형태가 `check_spacing`에서 다시 플래그되지 않는 것도 테스트로 고정.
- **범위**: 제47항 보조 용언만(사용자 결정). ~~제46항·제50항은 붙임/띄움 판정 로직 자체가 없어~~ **정정(2026-08-02, §37 참고)**: 제50항은 `_TERM_COMPOUND_TAGS`로 붙여 쓴 형태를 보호하는 로직이 이미 있었다. 없던 것은 기준에 맞춰 통일하는 쪽이다. 제49항·제50항은 §37에서 혼용 감지로 처리했고, 제46항은 여전히 미착수다.

## 37. 고유명사·전문 용어 띄어쓰기 혼용 감지 (2026-08-02)

§36(제47항 원칙/허용 선택) 직후, 사용자가 "제49항·제50항 규칙도 이미 알려줬는데 빠지지 않았느냐"고 지적해 확인한 결과 실제로 빠져 있었다. 규칙 정리와 설계는 `PRD.md` §14.

- **내가 틀렸던 것**: §36에서 "제50항은 붙임/띄움 판정 로직 자체가 없다"고 적었는데 부정확했다. `_TERM_COMPOUND_TAGS`가 이미 있고 **붙여 쓴 전문 용어·고유명사를 보호**한다(kiwi가 쪼개자는 제안을 되돌림). 없던 것은 "기준에 맞춰 통일"하는 쪽이다. `PRD.md` §13과 이 로그 §36의 해당 줄을 정정했다.
- **실제 구멍**: 한 작품에 `만성 골수성 백혈병`과 `만성골수성백혈병`이 섞여 있어도 둘 다 통과했다. 사용자가 요구한 "한 작품 안에 섞이면 안 됨"이 제47항에서만 지켜지고 있었다.
- **왜 제47항처럼 자동 통일하지 않았나**: 붙이려면 어디까지가 한 용어인지 알아야 하는데(고유명사는 의미 단위, 전문 용어는 전체), 그 경계는 사전에 없고 문맥 추측이 필요하다. §5 원칙에 정면으로 걸려 자동 통일 대신 **혼용 감지 플래그**로 결정(사용자 선택).
- **판정은 문자열 비교만**: 공백을 지운 문자열이 같은데 표면형이 다르면 혼용. 추측이 없다.
- **함정 1 — 최대 구간만으로는 안 짝지어짐**: `만성 골수성 백혈병 진단`과 `만성골수성백혈병 치료`는 뒤에 붙는 말이 달라 최대 구간의 키가 서로 다르다. 부분 구간까지 후보로 내고, 같은 혼용이 여러 길이로 걸리면 가장 긴 것만 남기는 방식으로 해결.
- **함정 2 — 태그가 모자라 구간이 끊김**: `강력팀`의 `강력`은 XR(어근), `골수성`의 `성`은 XSN(접미사)이라 `_TERM_COMPOUND_TAGS`만으로는 구간이 중간에 끊겨 짝을 못 찾았다. 혼용 감지 전용으로 `_TERM_RUN_TAGS = _TERM_COMPOUND_TAGS | {XR, XSN}`를 따로 뒀다 — 기존 보호 로직의 태그 집합은 건드리지 않았다.
- **함정 3 — 다수결이 규정을 어기는 표기를 제안**: `세종대로`/`세종 대로`가 1회씩이면 단순 다수결·동률 규칙으로는 `세종 대로`(규정 위반)를 통일 후보로 제안하게 된다. 거리 이름의 `대로/로/가`를 띄어 쓴 표기를 후보 우선순위에서 맨 뒤로 미뤄 해결(`_violates_street_name_rule`). 이 형태를 그 자체로 오류 플래그하지는 않는다.
- **하지 않은 것**: `부분만 붙임` 판정(전문 용어에서 금지, 고유명사에서 허용 — 어느 쪽인지 아는 것 자체가 추측), 제46항.
- **검증**: pytest 168건 통과(신규 8건). `examples/sample.srt`는 결과·리포트 모두 이전과 완전히 동일 — 새 검사가 기존 문서에 노이즈를 더하지 않음을 확인했다.
- **부수적으로 발견한 기존 버그(미수정)**: `개나리길 입구에서 봐` -> `개나리길 입구에 서 봐`. 조사 `에서`를 `에`+`서다`로 갈라놓는 과교정으로, 이번 변경과 무관한 기존 동작이다. `docs/BACKLOG.md`에 등록했다.

## 38. 웹 서버 실사용 검증 중 발견 — 규정 위반 띄어쓰기 제안 (2026-08-02)

§37 직후, 실행 중인 웹 서버(`/api/correct`)에 샘플을 실제로 올려 검증하다가 발견했다. 코드/테스트만으로는 안 보였고 결과 화면을 사람 눈으로 읽어야 드러나는 종류였다.

- **증상**: `만성골수성백혈병 치료는 길다`에 대해 `check_spacing`이 `만성골수성 백혈병 치료는 길다`를 제안했다. 전문 용어는 붙이려면 전부 붙여야 하므로(제50항) 이건 **규정에 어긋나는 부분 붙임을 사람에게 권하는** 제안이다. `마포경찰서 강력팀이` -> `마포경찰서 강력 팀이`도 같은 유형. 게다가 §37의 혼용 플래그와 같은 줄에 서로 모순되는 제안이 동시에 떴다.
- **원인**: `_protect_unfounded_respacing`의 전문 용어 보호가 `_TERM_COMPOUND_TAGS`(NNG/NNP/SN/SL/XPN/NR)만 봐서, 어근(XR: '강력')과 명사 파생 접미사(XSN: '골수성'의 '성') 경계에 공백을 끼워 넣자는 제안이 보호를 통과했다. §37에서 혼용 후보 구간이 끊기던 것과 **같은 태그 구멍**이다.
- **수정**: 그 판정만 `_TERM_RUN_TAGS`(= `_TERM_COMPOUND_TAGS` + XR + XSN)로 넓혔다. XR·XSN은 앞말과 항상 붙는 형태소라 그 자리에 공백이 들어갈 근거가 애초에 없다.
- **검증**: pytest 168건 통과(기존 테스트 전부 유지 — 넓힌 보호가 정당한 교정을 막지 않음). 혼용 샘플의 확인 필요 항목이 5건에서 3건으로 줄었고(부분 붙임 제안 2건 제거), 남은 3건은 전부 혼용 플래그다. `examples/sample.srt` 결과·로그·플래그는 이전과 동일.
- **교훈**: 테스트가 전부 통과해도 "사람에게 무엇을 보여주는가"는 실제로 화면을 봐야 안다. `PRD.md`의 "실제 텍스트로 돌려서 검증한다" 관례에 **결과 화면을 규정과 대조하는 것**까지 포함할 것.

## 39. 문서 전체 사투리 설정 — 일반 글용 (2026-08-02)

사용자 질문에서 출발: "일반 글은 글 전체가 사투리일 수 있다. 박경리 '토지'를 현대 표준어로 바꾸는 데도 이 교정기가 쓰였으면 한다."

- **확인한 사실**: 사투리 처리는 화자 이름이 있어야만 걸렸다(`resolve_dialect_mode`가 `speaker`를 `dialect_map`에서 찾지 못하면 `(None, None)`). 화자는 자막의 `[이름]` 표기에서 뽑으므로, **일반 글에서는 사투리 기능이 아예 동작하지 않았다.** 화면에는 "화자별 사투리 설정"만 있어서 이 사실이 드러나지 않았다.
- **변경**: `resolve_dialect_mode(..., document_region, document_mode)` — 화자별 지정이 우선이고, 없으면 문서 전체 설정으로 내려간다. `correct_entries(dialect_region=, dialect_mode=)`로 받아 모든 줄에 같은 값을 넘긴다.
- **기본값은 protect 유지**: 지역만 고르고 모드를 안 주면 보호다. 글 전체를 말없이 표준어로 바꾸는 것이 기본이 되면 안 된다.
- **지원하지 않는 지역명은 무시**한다(API·CLI 모두). 오타 하나로 글 전체가 엉뚱한 기준으로 처리되는 것보다 미지정이 안전하다.
- **노출**: `/api/correct`의 `dialect_region`·`dialect_mode` Form, `main.py --dialect-region/--dialect-mode`, 웹 UI 사투리 그룹 맨 위의 "문서 전체" 드롭다운 2개. 옵션 요약 줄에도 반영("문서 전체 경상도 사투리").
- **검증**: pytest 176건 통과(신규 8건). 화자 표기가 전혀 없는 `.txt`를 실제 서버에 올려 확인 — 설정 없으면 원문 그대로, `경상도`+`to_standard`면 "이거 아이가 마이시 좋다" -> "이거 그래 많이 좋다", 없는 지역명이면 원문 그대로.
- **알려진 한계(그대로 남음)**: 변환은 `convert_dialect()` 정적 매핑에 의존한다. 같은 검증에서 "밥은 뭇나 안 뭇나"는 바뀌지 않았다. 지역어 종합정보 API가 살아나기 전까지 문학 사투리 전면 표준어화는 부분적으로만 된다.
- **다음**: 사용 목적(자막/일반 글)에 따라 세부 설정을 갈라 보여주는 UI. 자막 쪽에는 글자 수·줄 수 검사(미구현)가 들어가야 칸이 채워진다.

## 41. 자막 구두점 규칙 3건 (2026-08-02)

사용자가 자막 모드 구두점 규칙을 직접 지정했다. 셋 다 자막 관례상 정답이 하나뿐이라 확인 플래그가 아니라 자동 교정이다. 일반 글 모드에는 하나도 적용하지 않는다 — "사용 목적을 자막으로 고른 경우에 한해"라는 조건이 이 대비로 구현된다.

1. **각 행 끝 마침표 생략** — 이미 구현돼 있었다(`correct_subtitle_final_period`, 커밋 `91989e4`에서 줄 단위로 보강). 실측으로 확인만 하고 손대지 않았다.
2. **행 중간 문장 사이 마침표 → 쉼표** — 기존 `check_subtitle_internal_period`(확인 플래그)를 `correct_subtitle_internal_period`(자동 교정)로 승격하고 옛 함수는 지웠다. 플래그였던 이유는 "문장 경계 판단은 사람이"였지만, 사용자가 자막에서는 이 자리에 쉼표를 쓰는 것이 확정 규칙이라고 지정했다.
3. **말줄임표 = 온점 세 개** — 신규 `correct_subtitle_ellipsis`. 말줄임표 문자(`…`, 연속이면 하나로)와 온점 네 개 이상(`......`)만 `...`로 바꾼다. 온점 하나·둘은 건드리지 않는다(하나는 마침표, 둘은 말줄임표로 단정할 근거 없음).

- **순서가 중요하다**: 말줄임표 통일 → 중간 마침표 → 줄 끝 마침표. 말줄임표를 먼저 `...`로 만들어야 뒤의 마침표 규칙이 `_is_sentence_period()`로 그것을 걸러 낼 수 있고, 중간 마침표를 쉼표로 바꾼 뒤 줄 끝을 지워야 `"보여 주세요. 궁금해요."`가 `"보여 주세요, 궁금해요"`로 한 번에 정리된다.
- **함정 — 편집 중 블록 중복**: 새 함수를 끼워 넣다가 `correct_subtitle_bracket_spacing`과 `_BRACKET_CLOSE_RESPACE_RE`가 통째로 두 번 들어갔다. import는 통과해서(뒤 정의가 앞을 덮어씀) 조용히 넘어갈 뻔했다. `grep -n "^def "`로 정의 목록을 확인해 잡았다. **큰 파일에 함수를 삽입한 뒤에는 정의 중복부터 확인할 것.**
- **검증**: pytest 195건 통과(신규 20건, `tests/test_subtitle_punctuation.py`). 기존 테스트 2건은 플래그를 기대하고 있어 자동 교정 기대값으로 고쳤다. 일반 글 모드 회귀도 함께 고정했다(`"보여 주세요. 궁금해요…"`가 그대로 유지되는지).
- **미결**: 인용부호 규칙(인용은 작은따옴표, 큰따옴표는 화면자막 등에만). 큰따옴표를 작은따옴표로 바꾸는 것 자체는 형태만 보면 되지만, "화면자막 등 기타 요소"라는 예외는 그 따옴표가 화면에 뜬 글자를 옮긴 것인지 인용인지 알아야 갈려 사전·형태 어디에도 근거가 없다. 사용자 결정 대기.

## 42. 자막 편집 표지 설정 + 줄 단위 파이프라인 분리 (2026-08-02)

§41 인용부호 논의에서 이어짐. 사용자가 "자막에는 사용자가 지정해야 하는 기술적 표지가 있고, 업계 공통 규칙이 없으니 그때그때 설정으로 받아야 안전하다"고 정리했다. 설계는 `PRD.md` §16.

- **§41의 미결이 여기서 풀렸다**: 큰따옴표를 작은따옴표로 바꿀지 물었던 문제의 답이 "따옴표는 화면자막 표지이므로 교정 대상이 아니다"였다. 표기를 바꾸는 규칙이 아니라 **제외 규칙**이 필요했던 것이다.
- **구조 변경(순수 이동)**: 화면자막을 "감싸인 구간만" 제외하려면 한 줄을 여러 조각으로 쪼개 일부만 교정해야 하는데, 파이프라인이 `correct_entries()` 반복문 안에 박혀 있어 그렇게 부를 수 없었다. 본문을 `_correct_line(index, text, doc_type, spacing_mode)`으로 그대로 떼어냈다. **이동 직후 195건이 그대로 통과하는 것을 먼저 확인한 뒤** 표지 로직을 얹었다.
- **함정 — 들여쓰기**: 반복문 안(8칸)에서 떼어낸 블록을 그대로 붙이면 `IndentationError`가 난다. `textwrap.dedent` 후 4칸으로 다시 넣었다. 편집이 꼬였을 때는 `git checkout -- <파일>`로 되돌리고 다시 하는 편이 빠르다(이번에도 그렇게 했다).
- **플래그를 줄 전체로 되돌리는 이유**: 구간 단위 교정의 플래그를 그대로 두면 `suggested_fix`가 조각이 된다. `apply_report_fixes()`는 `entry.text = fix`로 줄 전체를 덮어쓰므로, 조각이 들어가면 나머지 대사가 지워진다. 이 위험을 테스트로 고정했다(`test_flag_suggestion_covers_the_whole_line`).
- **검증**: pytest 208건 통과(신규 13건). 실제 서버 업로드로 확인 — 표지를 지정하면 `"초코렛. 세일중"`은 그대로, 표지 밖 `초코렛`은 `초콜릿`으로, `|` 앞 마침표는 줄 끝으로 보고 제거. 표지를 지정하지 않으면 예전처럼 전부 교정한다.

## 43. '말라 그래' 오교정 수정 + 화자명·어조 부호 설정 (2026-08-02)

사용자가 실사용에서 오교정 1건을 발견하고, 자막 편집 표지 설정에 두 항목을 더 요청했다.

- **오교정**: `지랄하시지 말라 그래.` -> `지랄하시지 말라, 그래`. 이건 "말라고 해"의 준말이라 '그래'가 감탄사가 아니라 인용을 받는 서술어인데, 쉼표가 들어가면 뜻이 갈라진다.
  - **원인**: kiwi는 문장부호가 붙어야("말라 그래.") 이 '그래'를 IC로 태깅한다. 마침표 없이 넣으면 VA-I+EF라 재현되지 않았다 — **오교정 재현은 사용자가 본 원문 그대로(문장부호 포함) 넣어야 한다.** 처음에 마침표를 빼고 넣어 "재현 안 됨"으로 오판할 뻔했다.
  - **수정**: `_is_quoted_command()` — '그래' 바로 앞이 인용 축약 어미(-라/-으라/-자/-냐/-마/-래)면 감탄사 쉼표 규칙을 건너뛴다. 동의의 '그래'("밥 먹자, 그래")와 겹치는 경계가 남지만, 안 넣어서 생기는 손해(사람이 직접 넣음)가 잘못 넣어서 생기는 손해(뜻이 바뀜)보다 작다.
- **화자명·어조 부호 설정**: OTT마다 대괄호와 괄호가 갈린다. `SubtitleMarkers`에 `speaker`·`tone`을 더하고, 하드코딩돼 있던 `correct_subtitle_bracket_spacing`의 `]`를 설정된 닫는 부호로 일반화했다. 한 글자만 적으면 짝을 채우고(`(` -> `()`), 짝 없는 문자는 기본값(대괄호)으로 떨어뜨린다 — 짝이 없으면 어디까지가 화자명인지 정할 수 없다.
  - **기본값은 대괄호 유지**: 지금까지의 동작이 대괄호 기준이라 기본값을 바꾸면 기존 사용자의 결과가 조용히 달라진다.
  - 설정하지 않은 부호는 건드리지 않는다(대괄호 원고에서 괄호까지 손대면 정당한 표기를 망친다).
- **검증**: pytest 218건 통과(신규 10건). 감탄사·호격 쉼표 규칙 자체가 살아 있는지도 회귀로 고정했다(`아이고, 어떻기는` / `먹어, 준희야` / `싫다면, 뭐`).

## 44. 실사용 오탐 2건 해결 — 감탄사 표제어 분할, 근거 없는 분리 제안 (2026-08-02)

`docs/BACKLOG.md` 18·19번을 사용자 요청으로 시험해 둘 다 해결했다.

- **19번(느낌표) — 진단이 어긋나 있었다.** 사용자는 "느낌표가 한 칸 띄워져 플래그됐다"고 보고했는데, kiwi가 느낌표 앞에 공백을 넣는 사례는 400여 조합을 돌려도 0건이었다. 실제 원인은 **감탄사 표제어 분할**이다: `에라이!` -> `에라,이!`, `아싸!` -> `아싸`가 아니라 `아,싸!`. kiwi가 `에라이`(표제어)를 `에라`(IC)+`이`로 쪼갠 분석을 믿고 감탄사 쉼표 규칙이 쉼표를 박았다. 앞 글자가 떨어져 나오니 "느낌표가 띄워진 것"처럼 보인 것이다. **플래그가 아니라 자동 교정이었다는 점에서 더 나빴다.**
  - 수정: `_inside_headword()` — 쉼표를 넣을 자리가 사전 표제어 한 단어 내부면 넣지 않는다. 사전이 kiwi 분석보다 권위 있다는 기존 원칙 그대로다.
- **18번(한짓골) — 검토안이 통과했다.** `_protect_unresolvable_splits()`: 분리로 생기는 조각이 전부 사전으로 설명될 때만 제안을 남긴다. `한짓골에` -> `한` + `짓골에`인데 `짓골`이 사전에 없으므로 취소.
  - **함정 ① 중간 상태 조회**: 삽입 지점 하나만 놓고 좌우를 보면 `먹을수있다`에서 `수있다`를 조회하게 되어 정당한 의존명사 제안이 죽는다. 삽입 지점을 **어절별로 모아 최종 조각 전체**를 봐야 한다.
  - **함정 ② 받침 공유 활용**: `됩니다`는 어간과 어미가 받침을 공유해 표면형으로 자를 수 없다. 이 갈래를 안 만들면 `안 됩니다` 제안이 함께 죽는다(실측에서 테스트 3건이 깨졌다).
  - **함정 ③ 되짚기가 너무 관대하면 규칙이 무력해진다**: 표면형으로 잘라 실패했는데 첫 형태소로 다시 봐주면 `짓골에`가 `짓`(표제어) 때문에 통과해 버린다. 되짚기는 **표면형으로 자를 수 없을 때만** 쓴다.
- **회귀 측정**: pytest 221건 통과, held-out 12/14(85.7%)로 기준선과 동일. 자동 교정(`오늘은 날씨가 좋네요`, `착오가 있었던`)과 정당한 제안(`안 됩니다`, `먹을 수 있다`)이 모두 유지되는 것을 확인했다.

## 45. '에서' 과교정 해결 — 합쳐 읽는 조사 후보가 있으면 갈라놓지 않는다 (2026-08-02)

`docs/BACKLOG.md` 15번. §37 작업 중 부수적으로 발견해 적어 둔 항목이다.

- **증상**: `개나리길 입구에서 봐` -> `개나리길 입구에 서 봐`. **자동 교정**이라 리포트를 봐도 눈에 잘 안 띄고, 대사의 뜻이 바뀐다.
- **원인**: 진짜 중의성이다. kiwi 1순위 분석이 `에`(JKB)+`서`(VV, 서다)+`어`(EC)이고, `_mechanical_respace`의 "조사 뒤는 새 어절" 규칙이 그 분석을 믿고 공백을 넣었다. 그런데 `입구에서 보자`(장소)와 `입구에 서 봐라`(서 있어라) 둘 다 문법적으로 가능하다 — 문맥이 정할 일이지 자동으로 고를 일이 아니다.
- **판정 근거는 kiwi 자신의 대안 분석**: `_kiwi.analyze(어절, top_n=5)`에 같은 자리에서 시작하면서 더 긴 조사 토큰(`에서`)이 있으면 "합쳐 읽는 읽기가 존재한다"는 **사실**이다(확률 비교가 아니다). 있으면 원문 간격을 보존하고 사람 확인에 맡긴다.
- **원문이 이미 띄어 쓰여 있으면 이 판정을 하지 않는다**: `거기에 서 봐`처럼 띄어 쓴 경우에는 합쳐 읽는 후보 자체가 생기지 않는다. 이 함수는 붙어 있는 경우에만 호출한다.
- **회귀 측정**: pytest 224건 통과(신규 2건), held-out 12/14로 기준선 동일. 조사·어미 결합 자동 교정(`오늘은날씨가좋네요` -> `오늘은 날씨가 좋네요`)은 그대로 살아 있다.

## 46. `engine.py` 모듈 분할 — 3,172줄 한 파일에서 16개 모듈 패키지로 (2026-08-02)

`docs/BACKLOG.md` 14번. 로직은 한 줄도 바꾸지 않았다.

- **방식**: 손으로 옮기지 않고 스크립트로 옮겼다. `ast`로 최상위 심볼 136개의 블록(선행 주석 포함)을 통째로 떼어 모듈에 배치하고, 모듈 간 `import`는 심볼 참조 그래프에서 자동 생성했다. 사람이 옮기면 주석을 흘리거나 조용히 로직을 손보게 되는데, 이 프로젝트에서는 **주석이 판정 근거의 저장소**라 그 유실이 코드 유실과 같다.

## 47. `api.py` 정리 — 업로드 처리 중복 제거 + 리포트 조회 방어 (2026-08-02)

교정 로직은 건드리지 않았다. HTTP 계층의 중복과 빈틈만 정리했다.

- **업로드 검증 일원화**: 확장자 허용 목록·크기 제한·임시 파일 실체화가 `/api/correct`와 `/api/speakers`에 따로 적혀 있었다. `_read_upload()` + `_materialized()` 하나로 합쳤다. 따로 두면 한쪽만 고쳐져 "업로드 화면에서는 막히는데 다른 경로로는 통과한다"가 된다. 부수 효과로 `/api/speakers`도 PDF 30MB 한도를 함께 쓰게 됐다(같은 근거의 같은 규칙이므로 갈라 둘 이유가 없다).
- **`filename`이 없는 업로드**: `Path(file.filename)`이 `None`에 터지던 자리를 `file.filename or ""`로 막았다. 확장자 검사에서 400으로 걸린다.
- **리포트 id 검증**: `/api/reports/{id}`의 id는 PostgREST 필터 문자열(`id=eq.{...}`)에 그대로 들어간다. 쉼표 같은 문자가 섞이면 의도하지 않은 질의가 되므로, 저장할 때 쓰는 형식(uuid4)이 아니면 조회하지 않고 404로 돌려준다.
- **저장소 장애와 "없는 리포트" 구분**: `store.get_report()`가 네트워크 예외를 던지면 스택 트레이스와 함께 500이 나가던 것을 502로 바꿨다.
- **JSON 폼 파싱 일원화**: `dialect_map`/`dialect_modes`의 `json.loads` + 예외 처리 + dict 여부 확인을 `_parse_json_object()` 하나로. 함수 안에 있던 `import json`도 모듈 상단으로 올렸다.

## 48. `dictionary.py` 모듈 분할 — 통신과 판정을 가른다 (2026-08-02)

§46과 같은 방식(스크립트 이동 + AST 대조)으로 967줄 한 파일을 `subtitle_corrector/dictionary/` 패키지 4개 모듈로 나눴다. 로직 변경 없음, 최상위 문장 52개 전부 동일, 주석 유실 0건.

- `clients.py` — 국립국어원 오픈API 6종에 요청을 보내고 응답을 그대로 돌려준다. **판정하지 않는다.**
- `headwords.py` — "이 표기가 사전에 있는가"(`word_exists`·`compound_status`·`definition_markers`·`registered_ending` 등, 답이 있다/없다로 끝나는 조회)
- `terms.py` — "이 표기를 무엇으로 바꿔야 하는가"(규범 표기 재지정·전 용어·외래어 표기 용례·순화어. 사전이 **대안 표기까지** 확정해 준 경우만)
- `dialect.py` — 사투리 표지 사전과 지역 판정
- **경계를 이렇게 잡은 이유**: `docs/DESIGN_PRINCIPLES.md` 원리 4(조회 로직 버그 — 가진 데이터를 잘못된 판정으로 버림)는 거의 전부 판정 쪽에서 난다(`word_exists`가 우리말샘 비표준 동형이의어 때문에 표준국어대사전 등재를 무시하던 버그 등). 통신 코드와 섞여 있으면 "API가 못 준 것"과 "우리가 잘못 버린 것"이 한 파일 안에서 구분되지 않는다.
- **`load_dotenv()`는 `clients.py`에만 둔다** — API 키를 읽는 유일한 모듈이다.
- 호출부 변경 없음: `from subtitle_corrector.dictionary import ...`가 그대로 동작한다(`__init__.py` 파사드가 공개 API 24개를 재수출).

## 49. 분할 검증 중 발견한 잠복 크래시 — 조사+보조 용언 분리 분기 (2026-08-02)

§46 분할이 정확도를 떨어뜨리지 않았는지 검증하다가, **분할 이전부터 있던** 버그를 하나 찾았다. 분할이 만든 것이 아니다(옛 커밋을 꺼내 같은 입력으로 재현해 확인).

- **증상**: `알고는있다`·`보고는싶다`처럼 **조사와 보조 용언을 붙여 쓴 줄**이 들어오면 `NameError: name 'to_restore' is not defined`로 터진다. 교정 요청 전체가 죽으므로, 원고에 그런 줄이 하나만 있어도 파일 전체가 교정되지 않는다(웹은 500, CLI는 트레이스백).
- **원인**: 2026-08-02에 제47항 단서 규칙(앞말에 조사가 붙으면 그 뒤 보조 용언은 띄어 쓴다)을 `_protect_unfounded_joining()`에 넣고, 같은 규칙을 `_protect_unfounded_respacing()`에도 복사하면서 **저쪽 함수의 지역 변수 이름**(`to_restore`/`insert_at`)을 그대로 옮겨 적었다. 이 함수에는 그런 변수가 없다.
- **고친 내용**: 이 함수는 kiwi가 **넣자고 한** 공백을 다루므로, 조사+보조 용언 자리의 공백 삽입은 제47항 단서상 정답이다 — 되돌리지 않고 `continue`로 그대로 둔다. 바로 위 '안 되다' 분기와 같은 처리다. 반대 방향(붙이자는 제안)은 원래대로 `_protect_unfounded_joining()`이 막는다.
- **왜 테스트 276건이 못 잡았나**: 이 분기는 kiwi가 조사(J\*) 다음 보조 용언(VX) 사이에 공백을 **삽입**할 때만 열린다. 보통은 그 자리를 붙이자고 제안하므로(반대 방향) 실사용에서도 드물게만 열린다. 테스트 코퍼스·예제 자막 594줄에도 그런 줄이 없었다.
- **어떻게 찾았나**: `tools/check_names.py` — 모듈이 참조하는 전역 이름이 그 모듈에서 해석되는지 정적으로 확인한다. 실행 없이 이름 해석만으로 잡히는 부류다. 회귀 고정은 `tests/test_realusage_review.py::test_particle_before_auxiliary_split_is_kept`.
- **남은 관찰(고치지 않음)**: 고친 뒤 `보고는싶다`·`알고는있다`는 띄어쓰기 제안이 나오지만 `먹고는싶다`는 나오지 않는다. `_protect_unresolvable_splits`가 조각(`먹고는`)을 사전으로 확인하지 못해 보류하기 때문이다(`docs/BACKLOG.md` 18번과 같은 보수성). 크래시와 별개의 기존 동작이라 이번에 건드리지 않았다.

## 50. 리팩터링 안전망 두 가지를 저장소에 남김 (2026-08-02)

§46~§48이 정확도에 영향을 주지 않았음을 증명하려고 만든 도구를 일회용으로 버리지 않고 `tools/`에 남겼다. 다음 구조 변경에서도 같은 증명을 재현해야 한다.

- **`tools/diff_behavior.py`** — 실제 코퍼스(테스트 파일의 한글 문자열 + 예제 자막 + held-out 입력, 현재 594줄)를 여섯 가지 설정 조합으로 통과시켜 교정문·자동 교정 로그·플래그를 JSON으로 덤프하고 두 덤프를 대조한다. 옛 커밋은 `git archive`로 꺼내 `PYTHONPATH`만 바꿔 같은 덤프를 뜬다.
  - **§46~§48 검증 결과**: 분할 전 트리와 분할 후 트리의 덤프가 **SHA256까지 동일**(662,809바이트). 교정문 3,564줄, 자동 교정 1,423건, 플래그 503건 전부 일치, 차이 0건.
  - 주의: 실시간 사전 API를 호출하므로, 차이가 나면 먼저 **같은 트리에서 두 번 떠서** 대조해 API 일시 장애와 코드 차이를 구분할 것.
- **`tools/check_names.py`** — 위 §49를 찾아낸 검사. 모듈 분할·함수 이동 뒤에는 반드시 돌린다. import 하나를 빠뜨려도 import 시점에는 조용하고 실행 시점에만 터지기 때문이다.

**정확도에 대한 정직한 정리**: §46~§48은 정확도를 **올리는** 작업이 아니었다. 목표는 "0.000% 변화"였고 그것이 위 대조로 확인됐다. 실제로 정확도를 올린 것은 §49 크래시 수정 하나뿐이며, 그것도 새 규칙이 아니라 있던 규칙이 못 돌던 것을 돌게 한 것이다.
