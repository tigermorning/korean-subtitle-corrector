# 밀린 작업 목록

`PRD.md`에서 분리된 문서(2026-07-27). PRD.md는 잘 안 바뀌는 핵심 스펙만 담는 문서인데 이 목록은 항목이 끝나고 새로 생길 때마다 계속 바뀌므로 따로 뒀다.

**세션을 시작하면 다른 작업보다 먼저 이 파일을 읽고 사용자에게 보고할 것.**

**작성 이유**: 밀린 작업이 `PRD.md`·`docs/IMPLEMENTATION_LOG.md`·`docs/GRAMMAR_PRECEDENTS_TABLE.md`·§8 체크리스트에 흩어져 있어서 사용자가 존재 자체를 모르고 있었다. 앞으로 새 세션은 **다른 작업을 시작하기 전에 이 목록을 먼저 사용자에게 보고**하고, 위에서부터 처리한다. 항목을 끝내면 이 목록에서 지우고, 새로 미룬 일이 생기면 반드시 여기에 추가한다 — 다시 흩어지면 이 목록의 의미가 없다.

### 착수 가능 (근거 확보됨, 코드만 남음)

1. **유사 판례 검색 실측 감수** — 위 "바로 다음 할 일 ①" 참고. 사용자가 최우선으로 지정(2026-07-27). **확인: `PRECEDENTS`는 0건**이라 착수 불가 상태이므로 판례 채우기가 선행이다.
2. **§27 "명사+드리다" 오탐지 조사·구현** — **확인: `subtitle_corrector/`·`tests/` 전체에 "드리다" 언급 0건.** 손댄 적 없음. `docs/log-archive/2026-h2.md` §27 전체를 먼저 읽을 것.
3. **제42항 의존명사 6개(들/뿐/만/지/차/판) 코드 구현** — **확인: 코드 0건, 검증표는 완료**(`docs/GRAMMAR_PRECEDENTS_TABLE.md`에 6개 모두 판정 규칙 + `qna_seq` 근거 + 2026-07-20 확인일까지 기재). **단, 값싼 작업이 아니다** — 검증표 스스로 '차'는 접미사·의존명사 두 종류가 겹치는 3중 기능이라 "표면만으로 구분 불가, 100% 커버 불가능한 경우가 남을 수 있음", '들'은 "나열 구조를 감지해야 해 구현 난이도가 상대적으로 높음"이라고 적어 두었다. 6개 모두 단일 True/False 판정이 아니라 **문맥 규칙**으로 구현해야 한다. 착수 시 `qna_seq` 인용을 다시 확인할 것(2026-07-20 배치에서 404가 1건 있었다).
4. **제44항 수 표기("몇만/몇백만") 자동교정 승격** — **확인: "몇만"·"몇백만"에 대한 코드·테스트 0건.** 이전 기록의 "현재 플래그만"은 부정확하다. 플래그도 없고 아무 처리도 없다. 제44항 관련 기존 테스트는 `tests/test_engine.py:286`의 "20만 명"을 쪼개지 않는지 확인하는 것뿐이라 이 항목과는 별개다.

### 외부 요인 대기 / 규모 큼

5. **`search_dialect()` — 확인 완료(2026-07-27), 우리 쪽 작업 없음** — 서버측 500 장애가 지속된다. 원 요청(`requests.get`)으로 `정구지`·`머스마`·`무싯날`·`감자` 4개 질의를 보냈고 **전부 HTTP 500 + HTML 오류 페이지**를 받았다. 기존 문서 기록("non-JSON 반환으로 사실상 중단")이 맞았다 — 앞서 이 항목에 "상태가 문서와 다르다"고 적은 것은 오판이었다. `search_dialect()`가 실패를 삼키고 `[]`를 돌려주는 것을 "정상 응답, 매칭 없음"으로 잘못 읽었기 때문이다. **상태 확인은 반드시 원 요청으로 할 것.** 서버가 복구되기 전에는 할 일이 없다.
6. **표준국어대사전 사전 내용 API(`view.do`)** — **확인: 코드 0건.** 용례·`norm_info`(한글 맞춤법 근거) 확인용. 근거 품질을 올릴 여지.
7. **온라인가나다 연동 2단계** — **확인: 코드 0건**(`docs/GRAMMAR_PRECEDENTS_TABLE.md` 문서에만 `qna_seq` 언급). 남은 작업 중 최대 규모. 깔끔한 API가 없어 검색/크롤링 방법 조사부터 필요(§8).
8. **Render 배포 재시도 여부 결정** — 작업이 아니라 사용자 결정 사항. 2026-07-22 kiwipiepy 메모리(약 310MB)로 무료 티어 512MB 초과, 502로 보류 중. 참고: `engine.py:111`의 `_kiwi = Kiwi()`가 import 시점 즉시 로딩이라 지연 로딩으로 바꾸면 **기동은** 통과하지만, 첫 교정 요청에서 같은 한도에 다시 부딪히므로 근본 해결은 아니다.

### 리팩터링

14. **`engine.py` 모듈 분할 (2,222줄 / 121,524자)** — 이 프로젝트에서 세션 토큰이 크게 나가는 첫 번째 원인은 이 파일 하나다(참고로 kiwipiepy는 로컬 C++ 분석기라 토큰을 전혀 쓰지 않는다 — 310MB는 메모리 비용이고 토큰과 무관하다. 2026-07-27 확인). 공개 함수는 `correct_*`/`check_*` 22개 + `correct_entries`(2010행)이고, 이미 기능별로 뭉쳐 있어 경계가 뚜렷하다. 제안하는 분할:
    - `kiwi_adapter.py` — `_kiwi` 싱글턴, `register_custom_words`, `_straddling_tokens`/`_token_containing`/`_tokenization_unstable_near` 등 토큰 조회 도구
    - `spacing.py` — `_mechanical_respace`, `correct_particle_spacing`, `correct_compound_spacing`, `correct_aux_verb_spacing`, `_protect_unfounded_joining`
    - `replacements.py` — `correct_always_wrong`, `correct_nonstandard_terms`, `correct_discriminatory_terms`, `correct_former_terms`, `_apply_replacements`, 조사 이형태 처리
    - `spelling.py` — `check_spelling`과 그 판정 도구(`_tensified_headword_variant`, `_is_reduplication`, `_is_native_compound`, `_unknown_content_words`)
    - `loanwords.py` / `subtitle.py` / `dialect.py` — 외래어, 자막 전용 부호 규칙, 사투리 모드
    - `engine.py` — `correct_entries` 오케스트레이션만 남긴다
    - **반드시 지킬 것 ①**: 순수 이동만 한다. 로직을 함께 손보면 150건 테스트가 회귀를 잡아주는 효과가 사라진다. 이동 후 전체 테스트가 그대로 통과해야 하고, 통과하지 않으면 이동이 잘못된 것이다.
    - **반드시 지킬 것 ②**: `_kiwi`는 프로세스에 **하나만** 있어야 한다. 모듈마다 `Kiwi()`를 만들면 메모리가 배로 늘고(§10 배포 한도와 직결), `register_custom_words()`로 등록한 고유명사가 다른 모듈에 전달되지 않아 "kiwi가 이름을 쪼개는" 버그가 되살아난다. 반드시 `kiwi_adapter.py` 하나에서 만들고 나머지는 import만 한다.
    - **기대 효과의 한계**: 엔진 전체를 봐야 하는 작업에서는 토큰이 줄지 않는다. 한 영역만 건드리는 작업(예: 띄어쓰기 규칙 하나 추가)에서 파일 하나만 읽으면 되는 것이 이득이다.
