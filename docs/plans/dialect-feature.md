# 사투리 교정 기능 구현 계획

## 요구 사항 요약

전문 번역가가 사용하는 한국어 자막 교정기에 사투리 교정 기능을 추가한다.
- **수동 설정**: 사용자가 화자별 사투리 종류를 지정
- **자동 감지 플래그**: 사투리 패턴이 감지되면 "이 화자가 사투리를 쓰는 것 같다"고 플래그
- **핵심 원칙 유지**: 자동 교정이 아닌 플래그만 — "확률적 추측이 아닌 권위 있는 규범 근거 기반"

## 현재 상태 분석

| 항목 | 현재 상태 | 필요 |
|---|---|---|
| 화자 정보 | SDH 브래킷(`[이름]`)이 text 일부로 보존됨 | 화자별 구조화 필요 |
| `search_dialect()` | dictionary.py에 존재, API 연동 완료 | engine.py 연결 필요 |
| 사투리 사전 | 없음 (정적 목록 없음) | 지역어 API 기반 구축 필요 |
| CLI 옵션 | `--names`만 있음 | `--dialect` 옵션 추가 필요 |

## 구현 방식: 3단계

### 1단계: 화자 추출 + 사투리 설정 구조 (기반)

**`parsers.py` 변경:**
- `SubtitleEntry`에 `speaker: str | None` 필드 추가
- `parse_srt()`가 브래킷 패턴 `[이름]` 또는 `[이름/상황]`에서 화자 이름 추출
- 화자가 없으면 `None`

**`main.py` 변경:**
- `--dialect` CLI 옵션 추가: `--dialect "민수:경상도" --dialect "영희:제주도"`
- 또는 `--dialect-file` 옵션으로 JSON 파일에서 읽기:
  ```json
  {
    "민수": "경상도",
    "영희": "제주도"
  }
  ```

**`engine.py` 변경:**
- `correct_entries()`가 화자 정보를 사용할 수 있도록 구조 개선
- `check_dialect()` 함수 시그니처에 `speaker: str | None` 추가

### 2단계: 사투리 감지 + 플래그 (핵심)

**`dictionary.py` — 사투리 매핑 사전:**

지역어 API가 단어 단위 검색이므로, 자주 쓰이는 사투리→표준어 매핑을 로컬에 둔다:

```python
# 자주 쓰이는 사투리 마커 (지역별 어미·조사 패턴)
DIALECT_MARKERS = {
    "경상도": {
        "어미": ["스라", "나요", "라요", "이까", "으이라", "니", "다イラ"],
        "조사": ["한테루", "한테가", "한테서"],
        "어휘": ["마이시", "예뿌다", "기раб다", "좋다"],
    },
    "제주도": {
        "어미": ["수다", "주와", "수과", "ᄒᆞ다", "ありが다", "이우다"],
        "조사": ["한테가", "한데서"],
        "어휘": ["하르방", "AĞᆞ리", "꼬닥"],
    },
    "전라도": {
        "어미": ["이", "라", "재", "네", "수룩"],
        "조사": ["한테랑", "한테나"],
        "어휘": ["아주머니", "총각"],
    },
    "충청도": {
        "어미": ["지", "제", "쥬", "유"],
        "어휘": ["adio", "기냥"],
    },
}
```

**`engine.py` — `check_dialect()` 함수:**

```python
def check_dialect(
    index: int,
    text: str,
    speaker: str | None,
    dialect_map: dict[str, str] | None,
) -> FlagItem | None:
    """화자에게 지정된 사투리가 있으면, 해당 화자의 대사에서 사투리
    패턴을 감지해 플래그한다.

    1. 화자에게 사투리가 지정되어 있으면:
       - search_dialect()로 해당 사투리↔표준어 조회
       - 사투리 패턴이 감지되면 플래그

    2. 화자에게 사투리가 지정되어 있지 않으면:
       - DIALECT_MARKERS로 사투리 패턴 감지
       - 일정 비율(50%) 이상이면 "이 화자가 사투리를 쓰는 것 같다" 플래그
    """
```

**감지 로직:**
- 정규표현식으로 대사에서 사투리 어미·조사·어휘 패턴 매칭
- 매칭된 패턴이 대사의 핵심 내용어가 아닌 어미·조사에 집중
- 플래그 문구에 실제 감지된 패턴과 해당 사투리→표준어 대응 제시

### 3단계: API 연동 (강화)

- `search_dialect()`로 특정 사투리 용어의 표준어 대응 실시간 조회
- 정적 매핑에 없는 사투리도 API로 검색 가능
- API 실패 시 정적 매핑으로 fallback

## 구현 대상 파일

| 파일 | 변경 내용 |
|---|---|
| `subtitle_corrector/parsers.py` | `SubtitleEntry.speaker` 필드 추가, `parse_srt()` 화자 추출 |
| `subtitle_corrector/engine.py` | `check_dialect()` 함수 추가, `correct_entries()`에서 화자 정보 전달 |
| `subtitle_corrector/dictionary.py` | `DIALECT_MARKERS` 상수 추가, `search_dialect()` 재사용 |
| `main.py` | `--dialect` / `--dialect-file` CLI 옵션 추가 |
| `subtitle_corrector/report.py` | 리포트에 `speaker` 컬럼 추가 (선택) |

## 수용 기준 (테스트 가능)

1. SDH 브래킷에서 화자 이름이 정확히 추출됨
2. `--dialect "민수:경상도"` 옵션 시 민수 화자의 대사에서 경상도 사투리 패턴이 플래그됨
3. 사투리 지정 없는 화자에서 사투리 패턴 50% 초과 시 자동 감지 플래그 발생
4. 기존 회귀 테스트(`examples/sample.srt`) 결과 변동 없음
5. `search_dialect()` API 실패 시 정적 매핑으로 안전하게 fallback

## 위험 요소 완화

| 위험 | 완화 |
|---|---|
| 사투리↔표준어 매핑이 불완전 | 플래그만 하고 자동 교정 안 함, 사용자 최종 확인 |
| 오탐지(표준어를 사투리로 잘못 감지) | 핵심 내용어가 아닌 어미·조사에만 패턴 매칭, 임계값(50%) 적용 |
| API 속도 저하 | `search_dialect()`에 `@lru_cache`, 정적 매핑 우선 사용 |
| 화자 브래킷 형식 불일치 | 다양한 브래킷 패턴 지원 (`[이름]`, `[이름/상황]`, `[이름: 상황]`) |

## 검증 단계

1. `examples/sample.srt`로 회귀 테스트 (기존 결과 변동 확인)
2. 사투리가 포함된 샘플 자막으로 플래그 테스트
3. `--dialect` 옵션 없이 실행 시 기존 동작 유지 확인
4. `--dialect` 옵션 있을 때 올바른 화자에게만 플래그 발생 확인
5. 전체 83개 기존 테스트 통과 확인
