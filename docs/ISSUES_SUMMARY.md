## A. 오탐지·과교정 버그 (해결됨) — 5가지 원리로 분류

`docs/DESIGN_PRINCIPLES.md`가 정리한 반복 원인 5가지. 새 버그가 나오면 이 중
하나의 재발인 경우가 대부분이었다.

1. **조각 대조(fragment-flagging)** — kiwi가 쪼갠 토막만 사전 대조하고, 그 토막을
   포함하는 최대 사전-유효 구간을 확인 안 함. 예: 얄짤(→얄짤없다), 껄쩍(→껄쩍지근하다).
2. **모호할 때 자동 교정** — 정답이 하나로 안 정해지는데 자동으로 바꿈. 예: 본 집/본집.
3. **우연한 사전 충돌** — 인접 조각을 이어붙인 문자열이 무관한 표제어와 우연히 겹침.
   예: "집"(house)이 kornorms의 "jib→지브"와 겹쳐 잘못 치환.
4. **조회 로직 버그** — 가진 데이터를 잘못된 판정으로 버림. 예: "흩어지다"가
   word_exists에서 혼합 표제어 때문에 통째로 비표준 처리됨.
5. **실패를 성공으로 흡수(2026-09-01 제안, 2026-09-02 원리 5로 승격, §84)** — 값
   하나로 "못 물어봤다"와 "물어봤더니 없더라"를 같이 돌려주면 장애가 정상 판정으로
   둔갑해 근거 없는 결론이 근거처럼 나간다. 앞의 넷과 달리 "가진 정보를 잘못
   판정"이 아니라 "정보가 없다는 사실 자체를 지움"이 원인. 지금까지 네 번:
   §62(우리말샘 '사전 불통' 과장), `search_dialect()`(지역어 장애·매칭없음 미구분),
   §78(모델 응답 형식 오류가 '고칠 것 없음'으로), §79(API 403이 '등재된 표기
   없음'으로). §84에서는 새 사고가 아니라 반대로 안전 확인이 나왔다 — 상위
   계층(`headwords.py`)이 자체 `except Exception:`으로 흡수해도 전역 실패 집계
   (`note_lookup_failure()`)가 새지 않는다는 걸 회귀 테스트로 고정했다.

### 실사용 감수에서 실제로 잡은 버그 (구현 완료, `docs/IMPLEMENTATION_LOG.md` §58~80 요약)

- **§58** 자동 교정 규칙 전수 점검 — 긍정 근거(사전에 붙임형이 있다는 사실만)로
  텍스트를 바꾸는 규칙이 사고를 낸다는 걸 확인. `정도 됩니다`→`정도됩니다`(定都되다와
  동형이의어 충돌) 등 7건.
- **§58②** 보조 용언 규칙이 사전 하이픈 표기(`그럴-듯하다`)를 깨뜨림 — ETM 조건
  누락.
- **§59** UI에서 자동 교정을 줄 단위로 되돌릴 수 없던 비대칭 문제, 그리고 부수로
  잡은 심각한 버그 — 제안 반영이 `.srt`/`.vtt` 등 자막 형식 다운로드에서 사라짐
  (반영은 `entries.text`만 고치고 다운로드는 원문 `entries`를 씀).
- **§60** 붙임 규칙 3개가 같은 경계(`명사+하다`)를 서로 되돌리는 문제 — 순서 고정으로
  해결(순서를 바꾸면 결과가 원문 띄어쓰기에 따라 갈림).
- **§61** 외래어 음차 오류 — 원어 없이는 `러스`(Ruth→루스 vs Russ→러스)처럼 정답이
  갈리는 경우를 텍스트만으로 못 정함. 원어 입력칸 기능으로 보완.
- **§62** 우리말샘 사전 조회 실패 리포트가 "사전 불통"으로 과장 표시됨 — 실제론
  40줄 교정에 조회 1,119건 중 1건이 10초 타임아웃한 것뿐. 재시도·서킷브레이커·건수
  기반 문구로 수정.
- **§63** 평가셋 마지막 실패(`안절부절했다`→`안절부절못했다` 못 잡음, 표준어 규정
  제25항) — 형태소 경계에 '못'을 끼우는 방식으로 해결, held-out 41/41 = 100% 달성.
- **§64** 두 건 모두 "사전 표제어가 있다는 사실만으로 정답을 만들 수 없는 자리":
  제44항 수 표기(몇만 등) 자동교정 승격 불가로 종결, `쳐 하다`류는 대안 자체가 없어
  제안 없이 사유만 안내하도록 변경.
- **§65** 도로명 띄어쓰기(`세종 대로`) — 사전으로는 일반명사 '대로'와 구분 불가,
  앞말 품사 태그(NNP)로 판별.
- **§66** `쉴러병`→`실러병` 오제안 — 어문 규범(인명 용례)과 사전(전문 표제어) 근거가
  서로 다른 경우, 한쪽을 정답이라 우기지 않고 두 근거를 나란히 제시하도록 변경.
- **§67** `부탁드릴`을 `부탁 드릴`로 가르자던 오탐지 — 접미사 '-드리다'가 사전
  표제어인데도 파생어(`부탁드리다`) 자체는 미등재라 오탐지.
- **§68** 원어 입력칸 기능 실사용 감수에서 발견한 결함 3건 — 조사 이형태(`이/가`)
  하드코딩, 자동 교정 후 텍스트에 이미 없는 오표기에 헛플래그, **반영 버튼이 다른
  사람 이름을 넣는 심각한 버그**(원어 표기 성/이름 순서가 뒤집힌 경우 처리 누락).
- **§78** 언어 모델 패스의 출력 형식을 지시문에서 스키마로 옮김 — "JSON만 내라"는 지시문은
  부탁이라 확률적으로만 지켜진다(코드 주석이 이미 "모델은 종종 코드펜스를 붙인다"고 적고
  있었다). `response_format`으로 서버가 강제하게 하고, 지원하지 않는 서버에는 한 번만
  폴백한다. 아울러 **응답에서 목록을 못 꺼낸 것**과 **고칠 게 없는 것**을 구분해 로그로
  알린다(전에는 둘 다 조용한 빈 결과였다).
- **§79** 어문 규범 API(kornorms)가 User-Agent로 막혀 **외래어 교정이 통째로 죽어 있었다**
  — `python-requests` 기본 UA와 `curl` 403, 이름을 밝힌 UA 200. 키를 빼도 403이라 인증
  문제가 아니었다. 전체 스위트 16건 실패가 전부 여기서 나왔다. `clients.py`의 `requests.get`
  6곳에 프로그램 이름을 밝힌 헤더를 붙였다(브라우저 위장은 쓰지 않았다). 아울러
  `/api/loanword-source`가 조회 실패를 "등재된 용례가 없습니다"라고 **빨간 글씨로 단정**하던
  것을 `lookup_failed`로 갈랐다 — 서버가 죽은 날 번역가가 사실 아닌 근거로 판단하게 된다.
- **§80** 좌우 병합이 애매하면 후보를 버리는 대신 두 가능성을 보여 준다(BACKLOG 32번 해결).

### `docs/KNOWN_LIMITATIONS.md`에 남아 있는 주요 항목 (완료)

- 고유명사(NNP) 외래어 표기는 정답이 하나여도 절대 자동 반영 안 함 → 항상 확인
  플래그로 전환 (특정 작품·제품의 고정 고유 표기를 훼손할 위험 때문).
- 고유명사(인명)를 맞춤법 오류로 오탐지 — "민준" 같은 정상 이름이 사전 미등재라는
  이유로 오류 취급됨. NNP를 맞춤법 검사 대상에서 제외해 해결.
- 실제 뉴스 텍스트 검증 중 발견 — `correct_compound_spacing()`이 조사로 분리된
  "축"+"목"을 우연히 인접으로 오인해 "회전축목이"로 잘못 합침.
- 실제 블로그 텍스트 검증 중 발견 — "그때"/"쓴맛" 같은 이미 붙어 있는 게 맞는
  합성어를 kiwi가 갈라놓자고 제안해 오탐지.
- 우리말샘 병행 확인 추가 시 발견한 함정 2가지: (1) 우리말샘은 "포함" 매치라
  "스노우"로 검색하면 "스노우맨" 등도 걸림, (2) 우리말샘은 "이미 알려진 틀린 표기"도
  표제어로 등재해 둠(뜻풀이에 "⇒규범 표기는 …" 안내) — 존재 여부만으로 정답 판단하면
  안 됨.

## B. 인프라·운영 문제

- **Render 배포 실패 (2026-07-22, `docs/RETROSPECTIVE.md`)**: 자막 업로드·교정
  요청마다 502 에러, 로그에 에러 없이 조용히 죽음 → 원인은 메모리 한도 초과.
  형태소 분석기(kiwipiepy) 모델 하나를 메모리에 올리는 데만 약 310MB 필요, Render
  무료 티어 512MB 한도를 거의 다 소진. 가벼운 통계 모델 옵션도 최신 버전에서 빠져
  있어 대체 불가. **배포 시도를 접기로 결정**(고칠 방법이 없어서가 아니라 시간
  배분 판단) — 여전히 로컬에서만 동작.
- **어문 규범 API User-Agent 차단 (2026-09-01 발생·해결, §79)**: `korean.go.kr/kornorms`가
  도구 기본 User-Agent를 403으로 막기 시작했다. 실측 — `python-requests` 403, `curl` 403,
  이름을 밝힌 UA 200, 키 유무는 무관. **증상이 "서버 오류"가 아니라 "등재된 표기 없음"으로
  보였다**는 것이 이 사건의 핵심이다. 해결: `clients.py`에 `_HEADERS`를 두고 모든 조회에
  적용. 같은 기관의 다른 API에는 아직 이 차단이 없지만 한곳에 모아 뒀다. 회귀 시험은
  `tests/test_lookup_failure_report.py::TestUserAgent`.
- **지역어 종합 정보 API 서버 500 장애 (외부 요인, 지속 중)**: `dialect.korean.go.kr`
  openAPI 엔드포인트가 모든 질의에 HTTP 500 반환. 우리 코드는 실패를 흡수해 `[]`
  반환하므로 "장애"와 "매칭 없음"이 구분 안 됨 — 상태 확인은 반드시 원 요청으로
  할 것. 사투리 assist의 표준어→사투리 역방향이 막힌 근본 원인.
  **2026-09-01 재확인: 여전히 500이다.** 같은 날 kornorms의 403이 UA 차단으로 밝혀져
  이쪽도 같은 원인인지 확인했으나 아니었다 — 헤더를 붙여도 500이다.

## C. 외부 코드 리뷰에서 지적된 문제 (`docs/Review.md`, `docs/Review_v2.md`)

리뷰이(신서연) 자신의 도구가 아니라 **AIFFEL 피어 리뷰**에서 리뷰어가 지적한
항목. 코드 결함이라기보다 제품/보안 미비점:

- **인증이 전혀 없음** — `/api/correct`, `/api/reports/{id}` 어디에도 접근 통제
  없음. report_id가 UUIDv4라 무작위 추측은 어렵지만 "링크를 아는 사람은 누구나
  접근 가능"한 설계.
- **요청 크기 제한·레이트 리밋 없음** — 요청 1건당 국립국어원 API를 토큰 수만큼
  반복 호출하는 구조라, 큰 파일을 반복 업로드하면 API 키의 일일 한도를 타인이
  소진시키거나 서버 리소스를 소모시킬 수 있음.
- **필수 환경변수 부재를 시작 시점에 감지 못 함** — API 키가 없으면 부팅은
  성공하고, 첫 요청이 들어와서야 `correct_entries()` 깊숙한 곳에서 `RuntimeError`로
  500 발생. Fail-fast 체크 없음.
- **`engine.py` 1,290줄로 코드량 절반 이상 차지** — 리뷰 시점 기준. **이후 실제로
  분할됨**(2026-08-02, `docs/log-archive/2026-h2.md` §46, `AGENTS.md` 참고) —
  이 지적은 이미 해소됨.
- **보조 용언 패턴 판정 로직 중복** — `_aux_verb_pattern_spans()`와
  `correct_aux_verb_spacing()` 내부가 같은 조건을 각자 다시 구현. 미해결로 남아
  있는지는 현재 코드 확인 필요.
- 테스트는 실시간 국립국어원 API 키가 있어야 통과하는 구조라, 리뷰어 환경에서
  `pytest` 전체 통과를 직접 확인하지 못함 — 두 리뷰 모두 공통 한계로 지적.

## E. 받아들인 한계 (재발 조건 없으면 손대지 않기로 한 것)

- **26번 — '명사+명사+하다'에서 놓치는 정당한 붙임**: 앞 명사가 관형어인지
  목적어인지 표면으로 못 갈라서, "붙여선 안 될 것을 붙이는 것"보다 "붙여야 할
  것을 못 붙이는 것"을 택함(`생일 선물 받았어`가 그대로 남음).
- **인명·지명 검증은 원어(로마자) 없이는 근본적 한계**: 이미 한글로 옮겨진
  고유명사만으로는 정확한 표기인지 검증 불가한 경우가 많음. 원어 입력칸(§61)이
  부분적으로 메웠지만 번역가가 원어를 남기지 않으면 여전히 못 잡음.
- **테스트셋 규모가 작음**: held-out 41건 100%는 이 41건에 한한 결과. 실사용
  감수에서 새 사례가 계속 나오는 것 자체가 이 한계의 증거.
- **규정 개정 추적이 전적으로 사람 손(세션 시작 시 점검 습관)에 달려 있음**:
  자동 감지 장치 없음.

## F. 회고에서 나온 교훈 (`docs/RETROSPECTIVE.md`)

- 한국어는 규범 세칙이 많고 맞춤법이 자주 바뀌며, "정답"이 고정된 게 아니라
  시점마다 달라서 이 도구는 "정답을 내놓는 것"보다 "현재 기준으로 가장 적절한
  안내를 하는 것"에 가깝다.
- 클라우드 로그에 에러가 없다고 "괜찮다"가 아니라 "응답 전에 죽었다"는 신호일
  수 있다(Render 502 사고에서 얻은 교훈).
- 남은 작업이 여러 문서에 흩어져 있으면 "이미 끝났는데 미구현으로 남은 기록"이
  생긴다 — 2026-07-27에 `docs/BACKLOG.md`로 한 목록에 모으면서 그런 사례 3건을
  실제로 발견함.
