## 13. kiwi 미등록 단어 오분석 대응 + .docx 지원 (구현 완료, 2026-07-16)

실제 대사(336줄 SDH 자막)로 검증하며 발견: 맞춤법/외래어/합성어 판단은 이미 사전(국립국어원)이 최종 근거인데, **띄어쓰기 제안(`check_spacing`)만 kiwi 자체 통계 모델(`kiwi.space()`)에 그대로 의존**하고 있어, kiwi가 모르는 단어(고유명사, 새 합성어)를 통계적으로 잘못 쪼갬 — "연실"→"연 실", "탄두리치킨"→"탄두 리 치킨", "한잔하다"→"한잔 하다가".

- **`_protect_unfounded_respacing()`(engine.py)**: kiwi.space()가 원문에 없던 공백을 새로 끼워 넣는 지점마다 (a) 고유명사(NNP) 경계, (b) 사전에 이미 붙여 쓴 형태로 등재됨(용언은 표면형 대신 lemma로 비교해야 함 — "한잔"+"하"로는 사전에 없지만 "한잔"+"하다"는 있음), (c) "/" 바로 뒤나 자막 `[이름/상황]` 브래킷 안(한글 맞춤법이 다루는 대상이 아님) 중 하나면 되돌린다.
- **`register_custom_words(words, tag)`(engine.py, `Kiwi.add_user_word` 활용)**: 번역가가 이 파일에 나오는 고유명사·요리/음료 이름을 미리 알려주면 kiwi가 이후 절대 잘못 안 쪼갬 — 실증 확인(연실/덱스/테일즈/탄두리치킨 전부 해결). CLI(`--names`/`--dishes` 옵션, 파일 경로)와 웹(업로드 화면 "고유명사"/"요리·음료 이름" 입력창, `names`/`dishes` form 필드) 둘 다 반영.
- **`check_spelling()` 플래그 문구 개선**: "사전에 없는 단어"만 말하던 걸, 외국어 음차·고유명사일 수 있다는 점과 사용자의 번역가 교육자료(구글 문서)가 권장하는 실제 검증 방법(국립국어원 용례, 발음기호 사전 Longman/Collins, 한글라이즈 hangulize.org)을 안내하도록 변경 — 그 문서가 "자동교정보다 수동 검증"을 강조하는 원칙을 그대로 반영.
- **`.docx` 지원(`parsers.parse_docx`)**: python-docx로 문단 텍스트를 읽어 다른 일반 텍스트와 동일하게 처리. 서식(볼드체 등) 보존은 이 도구의 범위 밖으로 명확히 둠 — 결과는 항상 순수 텍스트로 돌려준다(`write_plain_text` 재사용). 표 안의 텍스트는 다루지 않음(본문 문단만).
- **프론트엔드**: 더 이상 영상 자막에 국한되지 않는다는 점을 반영해 아이콘(🎬→📝)·제목 크기·설명 문구 정리("일반 텍스트, MS Word(.docx), 자막(.srt) 모두 그대로 업로드 가능"). 한글과컴퓨터(.hwp)는 아직 미구현이라 문구에 넣지 않음 — 넣게 되면 반드시 실제 구현 먼저.

**사용자의 번역가 교육자료(구글 문서) 전체 재검토 결과**: 문서는 29개 섹션(띄어쓰기, 동사/접사 판별, 보조용언, 숫자/단위, 문장부호, 외래어 IPA 세부 표기, 인명/지명/상표명 표기, 번역투/비문 판정 등)으로 이 도구의 v1 범위보다 훨씬 넓다. 재검토 후 판단:
- 대부분은 이미 `PRD.md` §2/`docs/KNOWN_LIMITATIONS.md`에서 "v1 범위 아님"으로 명시한 영역(외래어 표기법 세부 규칙 엔진은 "영어 하나만 다루는 것보다 훨씬 큰 작업, v2 이후 백로그"로 이미 기록됨) — 새로 발견된 게 아님.
- **문서 후반부 "번역투|오역|윤문" 섹션(비문 판정, 피동/사역 회피, 능동형 선호, 사물 주어 지양 등)은 아예 성격이 다른 카테고리** — "규정상 맞다/틀리다"가 아니라 번역 스타일 판단이라, 이 도구의 핵심 원칙("확률적 추측이 아닌 권위 있는 규범 근거 기반")으로 검증할 방법이 없다. 자동화 대상이 아님을 명확히 함.
- **북한어/방언 지양**: 이론적으로 사전 조회로 가능하지만, 이 프로젝트의 실제 입력(사투리 대사가 의도적으로 많은 드라마 대본 등)에서는 오히려 정상적인 캐릭터 화법을 전부 오탐지하게 될 위험이 커서, 구현하지 않기로 함(백로그로도 낮은 우선순위).
- **작게 반영할 만한 것(아직 안 함)**: "한번(행위)/한 번(수효)", "한잔(행위)/한 잔(수효)" 플래그에 문서의 구체적 구분 기준을 문구로 추가하면 도움될 것.

## 15. 고유명사 등록 통합/자동감지 + 실사용 오탐지 3건 수정 (구현 완료, 2026-07-16)

- **고유명사·요리/음료 입력창 통합**: 이름(NNP)과 요리/음료 이름(NNG)을 별도 태그로 등록했었는데, 이 프로젝트에서 이 태그는 "kiwi야 절대 쪼개지 마" 표시로만 쓰이고 다른 로직에 미치는 영향도 둘 다 원하는 방향과 같아 실질적 차이가 없었다. 웹 입력창 하나로 통합(CLI `--dishes` 옵션도 `--names`로 흡수).
- **`detect_recurring_unknown_words()`**: 문서 전체에서 사전에 없이 3번 이상 반복되는 명사를 자동 감지해 등록. 오타는 문서 전체에서 우연히 같은 형태로 반복될 가능성이 낮은 반면, 캐릭터 이름·요리명은 계속 같은 형태로 등장한다는 빈도 차이를 이용함. 번역가가 목록을 안 적어도 대부분의 고유명사 오분석이 해결됨 — 다만 kiwi가 애초에 여러 조각으로 쪼개는 단어(예: "탄두리치킨"->탄두+리+치킨)는 이 방식으로도 못 잡아 여전히 수동 등록이 필요.
- **`_token_containing()`**: kiwi.tokenize()가 이미 하나의 형태소로 본 토큰 **내부**에 kiwi.space()가 공백을 끼워 넣으려는 경우("연실"->"연 실")를 되돌림. tokenize()와 space()가 서로 다른 내부 모델이라 어긋난 것으로, 기존 `_straddling_tokens`(토큰 사이 경계만 확인)로는 못 잡던 사각지대였다.
- **실사용 문장에서 발견한 오탐지 3건, 전부 함수 단위(패턴)로 수정**:
  1. `_apply_replacements()`(차별적 표현·확정 오류 치환의 공통 로직)가 kiwi 토큰 경계 확인 없이 문자열 치환만 하다가, "재판장님"(재판장+님) 안에 우연히 들어있는 "장님"을 "시각장애인"으로 잘못 바꿈. 이제 매치 위치가 토큰 시작/끝과 정확히 일치할 때만 치환 — 검증 결과 "간질"(뇌전증) vs "간질이다"(간지럽히다, 무관한 동사)에서도 정확히 구분됨을 확인. `common_errors.py`의 8개 항목 전체에 일괄 적용됨(개별 단어별 예외 처리가 아님).
  2. `correct_aux_verb_spacing()`이 "보조용언은 원칙적으로 띄어쓴다"를 사전 등재 여부 확인 없이 강제 적용해 "여쭤보다"(표준국어대사전 등재)를 "여쭤 보다"로 잘못 쪼갬. `correct_compound_spacing()`이 명사 합성어를 사전으로 확인하는 것과 같은 원칙으로, 본용언-어/아 실제 표면형(축약형 그대로) + 보조용언 사전 기본형을 합친 후보를 `word_exists()`로 확인하도록 수정.
  3. `_mechanical_respace()`가 존대 보조사 "요"(이거요, 빨리요 등 아무 말에나 붙어 존댓말을 만드는 조사)를 kiwi가 가끔 관형사(MM) 등으로 잘못 태깅하는 걸 그대로 믿고 띄어쓰기를 강제("때만요"->"때만 요"). 원문에서 이미 붙어 있던 "요" 한 글자는 kiwi 태그가 무엇이든 그대로 두도록 예외 추가 — 진짜 관형사 "요"(요 녀석)라면 애초에 띄어 쓰여 있었을 것이므로 안전함.
- **웹 UI 레이아웃**: 2단(그리드) 레이아웃을 시도했다가 사용자가 "제목→소개→하는 일→고유명사→업로드" 순서의 단일 컬럼을 요청해 재변경. 본문 폭 1500px로 확대(양옆 여백 축소), "이 교정기가 하는 일" 박스는 4개 항목을 2x2 그리드로 배치해 세로 공간 절약. 체크마크/구분선 스타일은 사용자가 명시적으로 거부해 뺌.

## 17. 온라인가나다 판례 축적 (구현 완료, 2026-07-17)

`correct_aux_verb_spacing()` 패턴 2("할만하다"류) 검증 과정에서, 규칙에는 표준국어대사전만으로는 알 수 없는 예외가 있고 이런 예외를 확실히 잡으려면 온라인가나다(국립국어원 상담 게시판)까지 확인해야 한다는 점이 드러났다. 온라인가나다는 공식 검색/크롤링 API가 없어 매 교정 요청마다 실시간 조회할 수는 없다.

- **`subtitle_corrector/gananda_precedents.py`(신규)**: `common_errors.py`와 같은 방식의 정적 참고 데이터 파일. `expression`/`correct`/`source`(질문·답변 요지)/`verified`(확인 날짜) 필드를 가진 판례 리스트, `check_precedent(expression)`이 조회 함수.
- **`dictionary.py`의 `word_exists()`에 연동**: 표준국어대사전·우리말샘 실시간 조회 결과가 둘 다 없을 때만 마지막으로 이 판례를 확인 — 실시간 사전 데이터가 항상 우선이라는 원칙(`PRD.md` §5)은 그대로 유지하고, 판례는 사전에 답이 아예 없는 빈틈만 메운다.
- **채우는 방식**: (1) 실제 사용 중 애매한 사례를 만날 때마다 그 자리에서 검증해 수동으로 추가, (2) 예약 작업 `gananda-precedent-research`(매주 목요일 오전, `~/.claude/scheduled-tasks/`에 등록 — 2026-07-21 이전엔 월요일이었으나 사용자가 목요일로 변경)가 `PRD.md`/`docs/KNOWN_LIMITATIONS.md`와 `_AUX_NNB_FORMS` 같은 코드를 스스로 읽어 아직 다루지 않은 후보를 골라 WebSearch로 온라인가나다 답변을 찾고, 국립국어원 공식 출처로 명확히 확인된 것만 추가한다. 답이 조건부이거나 출처가 불명확하면 억지로 채우지 않고 건너뛰도록 명시함 — 개수보다 정확성 우선.
- **아직 안 한 것**: 예약 작업이 실제로 몇 차례 돌면서 판례가 얼마나 쌓이는지, 그리고 축적된 판례가 실제 오탐지를 얼마나 줄이는지는 검증 전. `PRECEDENTS` 리스트는 현재 비어 있음(0건) — 앞으로 실사용/예약 작업을 거치며 채워진다.

### 하드코딩된 검증 가정을 실시간 조회로 교체 (구현 완료, 2026-07-17)

사용자가 "-ㄹ 만하다"는 사실 표준국어대사전에 있는데(실제로 "만-하다"가 보조 형용사로 등재됨을 API로 확인) AI가 이걸 잘 못 찾는 것 같다고 지적함. 원인 분석 결과, 패턴 2의 (c) 처리("의존명사+하다/싶다 사이는 항상 붙임")가 실제로는 지난 세션에 9개 의존명사(뻔/만/법/듯/성/직/척/체/양)를 한 번 수동으로 확인한 뒤 **그 결과를 코드 주석에 "항상 참"이라고 하드코딩**한 것이었음 — 매 실행마다 다시 확인하는 게 아니었다. `word_exists("할만하다")`(특정 본용언이 붙은 전체 표면형)로 조회하면 0건이 나오는 게 맞지만(이 형태 자체는 개별 표제어가 아니므로), `word_exists("만하다")`(의존명사+하다 단독)로 조회하면 등재된 걸 확인할 수 있는데, 원래 코드는 이 후자 조회를 하지 않았다.

- **수정**: `correct_aux_verb_spacing()` 패턴 2의 (c) 분기를 하드코딩된 가정 대신 `word_exists(cur.form + nxt_citation)`(의존명사+하다/싶다 단독 조합) 실시간 조회로 교체 — "실시간 사전 데이터가 항상 우선" 원칙을 이 지점에도 일관되게 적용. 만약 이 조회마저 실패하면(예: "만싶다"처럼 실제로 존재하지 않는 조합) 붙인다고 단정하지 않고 그대로 둔다(사람 확인 영역).
- **검증**: 할만하다/아는척하다/그럴법하다/날뻔했다/갈만하다 -> 정상 분리, 그럴듯하다/볼만하다(전체가 독립된 표제어로 등재된 경우) -> 그대로 둠, 전체 회귀(`examples/sample.srt`) 결과 동일(자동교정 6건/플래그 4건) — 하드코딩을 없앴지만 기존 동작은 그대로 유지됨을 확인.
- **이 사례가 보여주는 일반 원칙**: `word_exists()` 같은 검증 함수를 쓸 때, 후보 문자열 하나(특히 가장 복잡하게 재구성한 전체 표면형)만 조회하고 실패하면 "사전에 없다"고 단정하면 안 된다 — 사전 표제어 표기 관례(하이픈 결합형, 특정 본용언 없이 추상화된 형태 등)에 따라 더 단순한 형태로 조회하면 존재가 확인되는 경우가 있다. 앞으로 비슷한 검증 로직을 짤 때는 여러 조회 변형을 시도하는 걸 기본으로 한다.

위 하드코딩 사례를 계기로, "정확도를 특정 단어 하나가 아니라 전체적으로 어떻게 높일 것인가"를 논의함. 그동안 이 프로젝트의 회귀 검증은 전부 수동이었다 — PRD.md에 "검증 완료"라고 기록해 두고, 다음에 코드를 고칠 때마다 사람(AI)이 그 사례들을 기억해서 다시 실행해보는 방식이었고, 실제로 이 문서에는 테스트 코드가 하나도 없었다. 이는 "검증표 먼저, 코드는 나중"(`PRD.md` §5) 원칙을 문서(prose)로만 지키는 것이지, 기계적으로 강제하는 게 아니었다.

### 실사용 오탐지 발견: kiwi가 근거 없이 공백을 지워버리는(단어를 붙여버리는) 경우 미방지 (구현 완료, 2026-07-17)

실제 자막으로 웹 화면을 테스트하던 사용자가 두 가지를 보고함:

1. **"한짓골"(동네 이름, "한지"+"골")**: kiwi가 "한"(관형사)+"짓"(명사)+"골"(명사) 세 조각으로 잘못 쪼개 띄어쓰기 제안이 "한 짓 골"로 엉망이 됨 — 이미 문서화된 "kiwi가 처음부터 여러 조각으로 쪼개는 단어(탄두리치킨 등)는 자동 감지로 못 잡고 수동 등록이 필요하다"는 한계와 같은 종류. 코드 수정 대상 아님, 사용자가 고유명사 목록에 추가하면 해결됨.
2. **"그만하려고 합니다" -> "그만하려고합니다"(실제 버그)**: "-려고 하다"(의도를 나타내는 본동사 구성, 제47항 보조 용언 붙임 허용과 무관하게 항상 띄어 써야 함)를 `kiwi.space()`가 통계적으로 붙여 쓴 형태로 제안했는데, `check_spacing()`이 이 오류를 걸러내지 못했다.

원인: `_protect_unfounded_respacing()`은 "kiwi가 원문에 없던 공백을 근거 없이 새로 끼워 넣는 것"만 막고 있었고, **그 반대 방향("kiwi가 원문에 있던 공백을 근거 없이 지워버리는 것")은 애초에 아예 방지 로직 자체가 없었다** — "특정 단어 하나"가 아니라 이 방향 전체가 빠져 있었던 구조적 빈틈.

- **`_removed_space_points()`/`_protect_unfounded_joining()`(engine.py, 신규)**: `_inserted_space_ranges()`/`_protect_unfounded_respacing()`과 정확히 대칭되는 반대 방향 로직. kiwi가 지운 공백 지점마다, 그 앞뒤 두 토큰이 사전에 실제로 합쳐진 단어로 등재되어 있는지(`word_exists`) 확인하고, 아니면 공백을 되돌린다. `check_spacing()`의 보호 체인 마지막에 추가.
- **구현 중 발견한 함정**: 두 토큰 사이 공백이 정확히 하나였는지 확인할 때, 토큰의 표면형(`form`)을 이어붙여 원문과 비교하려 했더니 실패함 — "합니다"처럼 어간("하")과 다음 형태소("ᆸ니다")가 받침 하나를 공유해 표면형과 실제 글자가 어긋나는 kiwi 특성(제41항 관련 로직에서도 이미 확인된 문제) 때문. 표면형 재구성 비교 대신 토큰 위치(`start`/`len`) 기반으로 그 사이 간격만 직접 확인하도록 수정해 해결.
- **검증**: "그만하려고 합니다"/"나는 가려고 합니다"/"먹으려고 해요" 전부 더 이상 플래그되지 않음(일반화 확인 — 특정 동사 하나가 아니라 "-려고 하다" 패턴 전체에 적용됨). 기존 23개 테스트 전부 통과 + 회귀 테스트 2건 추가(`tests/test_engine.py::TestCheckSpacingJoiningProtection`). 실제 웹 화면(로컬 서버)에서도 최종 확인함.

### 배치 조사 1차 실행 결과: 추가 0건 (2026-07-17)

`_AUX_NNB_FORMS`(뻔/만/법/듯/성/직/척/체/양) 9개 전부에 대해 문법적으로 결합 가능한 하다/싶다 후보(뻔하다/만하다/법하다/듯하다/듯싶다/성싶다/직하다/척하다/체하다/양하다, 총 10개)를 만들어 `word_exists()`로 직접 조회한 결과, **10개 전부 표준국어대사전(`search_stdict`)에서 바로 표제어로 확인됨**("만-하다", "법-하다", "듯-하다", "듯-싶다", "성-싶다", "직-하다", "척-하다", "체-하다", "양-하다", "뻔-하다" 모두 `total >= 1`).

- 즉 이 9개 의존명사의 하다/싶다 결합형은 이미 실시간 사전 조회만으로 전부 해결되고 있어(§17 "하드코딩된 검증 가정을 실시간 조회로 교체" 항목에서 고친 바로 그 경로), 온라인가나다 판례가 필요한 빈틈이 하나도 없었다.
- 이번 조사 대상 선정 기준("두 사전 모두에 없을 가능성이 있는 것") 자체를 만족하는 후보가 없었으므로 온라인가나다 검색(WebSearch)까지 갈 필요도 없었음 — `PRECEDENTS`는 그대로 0건 유지.
- 앞으로 새 후보를 조사할 때도 이 순서(실시간 사전 조회로 먼저 걸러내기)를 유지하면, 실제 빈틈(두 사전 다 표제어가 없는 경우)에만 온라인가나다 조사 리소스를 쓸 수 있다.

### 배치 조사 2차 실행 결과: (A) 0건 / (B) 6건 추가 (2026-07-20)

## 19. 실제 다큐멘터리 자막 감수로 발견한 오탐지 무더기 수정 (구현 완료, 2026-07-17)

사용자가 실제 다큐멘터리 한글 자막본(전쟁 다큐멘터리, 군사 용어·편제 번호가 많음)으로 프로그램을 돌려본 결과, 서로 다른 단어처럼 보이지만 근본 원인은 단 세 가지로 좁혀지는 오탐지 8건을 한 번에 보고받음.

- **원인 1 — `_protect_unfounded_respacing()`의 사전 등재 확인 로직이 표면형 재구성 방식이라 축약형에서 깨짐**: "잘해야"(잘하다의 활용형, "해"="하"+"어"의 축약)를 "잘 해야"로 잘못 갈라놓음. `word_exists("잘하다")`는 True인데도, 코드가 `text[before.start:after.start+after.len] == before.form + after.form`(표면형을 그대로 이어붙여 비교)로 간격을 확인하다가 "잘"+"하"(재구성) != "잘해"(실제 글자)라 아예 검사를 건너뛰고 있었다 — §17에서 `_protect_unfounded_joining()`에 이미 적용했던 것과 정확히 같은 함정(어간+어미가 받침/음절을 공유하는 kiwi 특성)을 이 더 오래된 함수에는 아직 안 옮겨서 생김. `before.start + before.len == after.start`(위치 기반, 표면형 재구성 없음) 확인으로 교체.
- **원인 2 — 전문 용어·고유명사·편제 번호 복합어를 사전에 없다는 이유만으로 갈라놓음**: "제505공수보병연대원", "폭파병", "제82공수사단장", "제505공수보병연대 2대대", "E중대", "20만"(독일군 20만 명) 전부 같은 원인 — 이런 조합은 애초에 사전에 개별 표제어로 등재될 수 없을 만큼 무한히 다양한데(부대 번호 등), 한글 맞춤법 제49항(고유 명사)·제50항(전문 용어)이 "단어별로 띄어 씀을 원칙으로 하되, 붙여 쓸 수 있다"고 이미 명시적으로 허용하고, 제44항은 "만" 단위 이내 숫자는 붙여 쓴다고 규정한다. 즉 사전 등재 여부와 무관하게 이미 붙여 쓴 것 자체가 허용된 표기이므로, kiwi가 통계적으로 갈라놓자는 제안을 신뢰할 근거가 없다. `_TERM_COMPOUND_TAGS = {NNG, NNP, SN, SL, XPN, NR}` 신설 — 이 태그에 속하는 토큰끼리 원래 붙어 있었다면 사전 확인 없이 무조건 보호한다(NNP 단독 보호를 일반화한 것). 의존명사(NNB)는 제외 — 그건 제42항에 따라 실제로 항상 띄어 써야 하는 별개 규칙이라 포함하면 정당한 오류까지 숨기게 됨.
  - **트레이드오프(의도적)**: 이 일반화는 "완전히 다 붙여 쓴 일반 문장"(내용어 여러 개가 진짜 오타로 안 띄어 쓰인 경우)에 대한 띄어쓰기 제안도 함께 억제한다. 다만 이 도구의 실제 입력(번역가가 이미 정상적으로 띄어 쓴 자막)에서는 이런 경우가 드물고, 반대로 전문용어·고유명사 오탐지가 훨씬 흔하다는 실사용 근거(이번 8건)에 따라 노이즈를 줄이는 쪽을 택함 — "잘못된 수정보다 미수정이 낫다" 원칙과도 일치.
- **원인 3 — 생산적 파생어(국가명+군/인/어)를 사전 등재 여부만으로 신조어 취급**: "영국군"이 "사전에 없는 단어"로 플래그됨. `word_exists("영국군")`은 False인데 `word_exists("미군")`/`word_exists("독일군")`은 True — 사전이 이 계열 단어를 들쭉날쭉하게만 등재해 둔 것뿐, "국가명+군(軍)"은 규칙적으로 항상 만들 수 있는 정상적인 조합이다. `_is_productive_demonym_compound()`(접미사 군/인/어를 떼고 남은 부분이 `word_exists()`로 확인되면 신조어 취급 안 함) 신설, `check_spelling()`에 연동.
- **검증**: 8건 전부 실제 웹 화면(로컬 서버)에서 재확인, 기존 회귀 테스트 전부 통과 + 신규 테스트 6건 추가.
- **"마치다/맞히다" 목적어 기반 판별 추가 (구현 완료, 이후 §26에서 제거됨)**: "아르덴 전투 지역에 전개를 마칩니다"에서 이 플래그가 의미 없다는 지적에 대해, 사용자가 "두 단어의 의미를 확실히 파악해 혼동 오류를 없애 달라"고 명확히 요청함. 표준국어대사전 뜻풀이를 확인한 결과 "마치다"(일·과정이 끝나다)와 "맞히다"(정답/자연현상/의료 행위를 맞게 하다)는 목적어(를/을 앞 명사) 종류만 봐도 대부분 의미가 명확히 갈린다 — "전개를"/"수업을"처럼 활동성 명사가 목적어면 "맞히다"일 수가 없고, "정답을"/"문제를"처럼 답·자연현상성 명사가 목적어면 "마치다"일 수가 없다. `_MACHIDA_OBJECTS`/`_MAJIDA_OBJECTS`(사전 뜻풀이·용례 기반 전형적 목적어 목록)와 `_machida_majida_resolved()`를 추가해, 목적어가 한쪽 부류에만 속하고 실제 쓰인 동사도 그 부류와 일치하면 플래그를 생략한다. 목적어가 반대쪽 부류인데 다른 동사가 쓰였거나(예: "정답을 마쳤다", 실제 오류일 가능성 높음) 목적어가 둘 다 아니면 여전히 플래그한다. 이 쌍에만 적용된 예외적 처리였으며(2026-07-21, §26에서 제57항 검사 전체 제거로 이 로직도 함께 삭제됨).

## 20. 2차 실사용 감수: 확실한 버그 3건 수정 + 판단 필요한 사례 2건 발견 (2026-07-17)

같은 다큐멘터리 자막을 계속 감수하며 추가로 5건을 보고받음. 이번엔 "제대로 수정할 수 없는 오류는 추정하지 말고 반드시 확인해달라"는 사용자의 명확한 새 원칙에 따라, 확신 있는 것만 바로 고치고 나머지는 사용자에게 판단을 구했다.

- **확실한 버그로 확인되어 수정 완료**:
  1. **불규칙 활용 어간 태그 불일치**: kiwi가 불규칙 활용 어간(잇다의 "잇" 등)을 "VV"가 아니라 "VV-I"(하위분류 접미사)로 태깅하는데, `correct_aux_verb_spacing()`/`_aux_verb_pattern_spans()`의 패턴 1이 `prev.tag in ("VV", "VA")`(정확히 일치)로만 확인해 이런 동사가 낀 보조 용언 구성을 통째로 놓치고 있었다. "이어가다"(사전에 없음)가 이 버그 때문에 전용 로직을 타지 못하고 애매한 일반 플래그("문맥에 따라 정답이 다를 수 있음")로 새어나감 — `.startswith("VV")`/`.startswith("VA")`로 교체해 해결. 원래 의도대로 이제 사전 미등재 상태이므로 원칙(띄어쓰기)대로 "이어 가다"로 자동 교정됨.
  2. **"마치다/맞히다" 목적어 목록 보강**: "설치를 마쳤으며"가 목적어 목록에 "설치"가 없어 여전히 플래그되던 것 — "설치"/"공격"/"작전"을 `_MACHIDA_OBJECTS`에 추가.
  3. **"동음이의어" 용어 정정**: 사용자가 "마치다와 맞히다는 맞춤법(표기)이 다르기 때문에 동음이의어라고 볼 수 없다"고 지적 — 정확한 지적이다. "동음이의어"는 엄밀히는 표기·발음이 모두 같은 서로 다른 단어를 가리키는 용어라, 표기가 다른 이 혼동 쌍들에 쓰는 건 용어 오용이었다. 플래그 문구를 "한글 맞춤법 제57항: 소리가 비슷해 혼동하기 쉬운 말"로 정정.
- **사용자에게 확인 후 처리 완료**:
  1. **"안되다"/"안 되다" — 조건·전제 어미 기반 문맥 판별 추가 (구현 완료)**: 사용자가 "문맥에 의거해 의미로 구분하라"고 명확히 요청함. "안되다"(형용사)와 "안 되다"(부정 부사+동사)는 사전 등재만으로 구분이 안 되지만, "-면"/"-거든"/"-아서는·-어서는" 같은 조건·전제 어미 바로 뒤에 오는 "안 되다"는 사실상 예외 없이 금지·불가 구성이라는 확실한 문법적 근거가 있다. `_andoeda_forces_split()`(engine.py) 추가 — 이 신호가 있으면 사전 등재 여부와 무관하게 항상 띄어 쓰도록 `_protect_unfounded_respacing()`/`_protect_unfounded_joining()` 양쪽에 연동. 신호가 없는 나머지(예: "공부가 안된다")는 기존 사전 등재 판단(항상 붙임)을 그대로 따른다 — 확신 없는 나머지 경우까지 추정하지 않음.
     - **추가 검증 + 사각지대 보강 (2026-07-21)**: 사용자가 "그렇게 하시면 안됩니다"(='잘되다'의 반대 맥락, 붙임)와 "그렇게 하시면 안 됩니다"(='되다'의 부정, 띄어씀)라는 본인 구분을 제공. 표준국어대사전·우리말샘을 직접 재조회해 검증한 결과, "안-되다"(붙임) 표제어의 공식 뜻은 ①일·현상·물건이 좋게 이루어지지 않다 ②사람이 훌륭하게 되지 못하다 ③일정한 수준·정도에 이르지 못하다 ④섭섭하거나 가엾어 마음이 언짢다 ⑤근심·병으로 얼굴이 상하다, 이 다섯 개뿐이고 "허용되지 않음/금지"라는 뜻은 없음을 확인 — 사용자의 구분이 사전 근거와 정확히 일치한다. 온라인가나다 답변(qna_seq=324260, 326430, mcfaq_seq=8427 — WebFetch 요약 기반이라 인용 시 재확인 권장)도 "그런 짓을 하면 안 된다"류의 금지 구성은 띄어쓰기로 안내함. 이 검증 과정에서 기존 `_andoeda_forces_split()`이 조건 어미와 "안" 사이에 주어 등 다른 어절이 끼면 신호를 놓치는 사각지대를 실제 테스트로 발견함(예: "그렇게 급하게 진행하시면 결과가 안됩니다"가 플래그되지 않음) — `_conditional_marker_before()`를 추가해 체언·조사·부사만 있는 구간(최대 5토큰)은 건너뛰고 조건 어미를 찾도록 확장, 처음 만나는 어미(EC)가 조건형이 아니면 그 자리에서 탐색을 멈춰 다른 절의 조건 어미까지 잘못 끌어오지 않게 함. 회귀 테스트 2건 추가(`TestAndoedaContextDisambiguation`), 87개 전체 테스트 통과.
     - **미해결 캐뷰앳(백로그)**: 뜻풀이 ③("수준·정도 미달", 예: "나이가 서른도 안된 젊은이")은 온라인가나다의 일부 답변(qna_seq=324260, "만 원이 안 된다"/"600명이 안 된다")이 사전 표제어 뜻풀이와 다르게 띄어쓰기를 안내하고 있어, 국립국어원 스스로도 이 뜻풀이의 실제 적용에 결이 다른 답변이 존재하는 것으로 보인다. 현재 코드는 이 뜻풀이 ③ 케이스를 별도로 다루지 않고(조건 어미 신호가 없으면 기존 사전 등재 판단인 "붙임"을 그대로 따름) 있으므로, 실사용 중 "수량+안되다/안 되다" 오탐지가 보고되면 이 캐뷰앳부터 재조사할 것.
  2. **`compound_status()` 우연한 동형이의어 충돌 — 관형사+명사는 허용 목록 방식으로 전환 (구현 완료)**: "두 강"→"두강"(杜康=술의 별칭, 무관), "그 다리"→"그다리"("다리쇠"의 방언, 무관) 등 사전이 "합성어"라고 확인해 줘도 원문 의도와 무관한 우연한 충돌이 실제로 발견됨. 사용자는 "그때/그것/이것처럼 이미 사전에 등재된 조합만 허용하고, 나머지는 한 단어로 취급하지 않는다"는 방향을 확인 — 관형사(그/이/저/두/세 등)가 이끄는 조합만 `_MM_NOUN_COMPOUND_ALLOWLIST`(그때/그날/이날/그곳/이곳/저곳, 검증된 것만)로 제한하고, 그 외는 사전이 "합성어"라고 해도 자동으로 붙이지 않도록 `_compound_candidate_spans()` 수정. 명사+명사(NNG+NNG) 조합은 이번 결정 범위에 포함되지 않아 기존 방식(사전 등재 시 자동 붙임) 그대로 유지 — 즉 "강 다리"→"강다리"(장작 단위/받침나무, 무관) 같은 명사+명사 충돌은 아직 남아 있는 채로 의도적으로 남겨둠.
  3. **"이어가다"/"동음이의어" 용어/목적어 목록 등 나머지 3건**: 확신 있는 버그로 판단해 사용자 확인 없이 바로 수정(위 상단 참고).

## 21. 3차 실사용 감수: 오탐지 10건 조사 및 확실한 버그 8건 수정 (2026-07-17)

같은 다큐멘터리 자막을 계속 감수하며 10건을 추가로 보고받음. 실제 사전/토큰 분석으로 각각 검증한 뒤, 확신 있는 버그는 바로 고치고 나머지는 "판단이 필요한 사례"로 분리해 사용자에게 확인을 구했다.

- **`_opendict_item_is_standard()`의 "미확정" 오판 (구현 완료)**: "쉴더병"이 우리말샘에 있는데도 "사전에 없는 단어"로 플래그됨. 뜻풀이에 "⇒규범 표기는 미확정이다"라는 문구가 있었는데, 기존 코드는 "규범 표기는"이라는 문자열만 보고 "다른 대안 표기가 있다"(초코렛→초콜릿 같은 경우)는 뜻으로 오판했다. "미확정"(아직 정하지 못함, 대안이 없음)과 "다른 표기가 있음"은 다른 뜻이므로 구분하도록 수정.
- **3형태소 복합동사(어간+연결어미+동사)의 사전 확인 실패 (구현 완료)**: "기어다니다"("기다"+"어"+"다니다"), "데려다주다"("데리"+"어다"+"주다")가 잘못 갈라짐. `_protect_unfounded_respacing()`의 사전 등재 확인이 공백 삽입 지점 바로 양옆 토큰 두 개만 보고 후보를 만들다가, 연결어미(EC) 하나만으로는 사전 표제어와 비교가 안 되는 걸 놓치고 있었다("어다"+"주다"="어다주다"라는 없는 말이 후보가 됨). 연결어미 앞의 어간까지 찾아 실제 표면형("데려다")으로 후보를 만들도록 수정 — 어간과 어미가 위치를 살짝 겹치는 경우("데리"+"어다"="데려다")까지 포함.
- **"과"(조사 "~와/과" vs 접두사 "과-[過]") 동형이의어 (구현 완료)**: "좌심실 과증식 상태"에서 "과"가 조사로 오판되어 앞말("좌심실")에 강제로 붙어버림("좌심실과 증식"). "과"+뒷말이 사전에 등재된 단어("과증식")이고 이미 붙어 있으면 접두사로 보고 앞말에 붙이지 않도록 `_mechanical_respace()` 수정.
- **종결어미(EF) 보호 일반화 (구현 완료)**: "말했잖아요"→"말했잖아 요", "그냥요"→"그냥 요", "사람들은요"→"사람들은 요", "모범생 같잖아요"→"모범생 같잖 아요"— 전부 kiwi의 tokenize()/space()가 축약형("잖아요"="지"+"않"+"아요")을 서로 다르게 분석해 생긴 문제. 기존에 "요" 한 글자만 보호하던 걸, 종결어미(EF) 태그 전체로 일반화(`_mechanical_respace()`의 기존 원칙 — EF는 항상 앞말에 붙음 — 을 `check_spacing()`의 보호 로직에도 동일 적용).
- **숫자+기호("80%") 보호 (구현 완료)**: 숫자(SN)+기호(SW, %/$/# 등)는 사전 등재 여부와 무관하게 항상 붙여 쓰는 순수 표기 관례라 별도로 보호 추가.
- **`check_spelling()`에 kornorms(외래어 표기 용례) 보강 (구현 완료)**: "뉴암스테르담"이 표준국어대사전/우리말샘엔 없지만 국립국어원 외래어 용례(kornorms)엔 있다는 지적 — 실제로 재현되진 않았으나(kiwi가 NNP로 태깅해 이미 검사 대상에서 제외됨), 유사한 경우를 대비해 `check_spelling()`이 단어 하나를 최종적으로 "사전에 없음"으로 판정하기 전에 kornorms도 확인하도록 방어적으로 보강.
- **"시간이 없다잖나" 해결 (구현 완료, 2026-07-17)**: 당시엔 "잖" 한 글자에 "고 하지 않"까지 압축해서 분석하는 더 깊은 수준의 자기 불일치라 EF 일반화로도 못 잡고 미해결로 남겼던 사례 — §23 "kiwi는 참고일 뿐, 사전 표제어가 기준" 재설계로 해결. 상세 내용은 아래 §23 참고.
- **사용자에게 확인 후 처리 완료**:
  1. **"7년 전 일" -> "전일" 충돌 — 명사+명사 허용 목록이 아니라 문맥(선행 시간 표현) 기반으로 해결 (구현 완료)**: 사용자가 "이건 명사+명사로 설명할 수 없는 문제"라고 정확히 지적함 — "7년 전 일"(7년 전+일, 띄어야 함)과 "전일"(全日/前日, 붙여야 함)의 차이는 품사 조합이 아니라 "전" 앞에 시간 표현이 있느냐로 갈린다. §20에서 도입한 "명사+명사는 그대로 유지"라는 결정과는 별개로, "숫자+시간단위(년/월/일 등) 뒤에 오는 '전'은 뒤 명사와 절대 합성어가 될 수 없다"는 문법적으로 확실한 신호를 찾아 `_DURATION_UNIT_NNB` 기반 예외로 `_compound_candidate_spans()`에 추가.
  2. **"느리다/늘이다/늘리다", "주리다/줄이다"를 CONFUSABLE_PAIRS에서 제외 (구현 완료, 이후 §26에서 CONFUSABLE_PAIRS 전체 삭제)**: 사용자가 "우리는 글을 감수하는 것이므로 발음이 비슷한 것은 관계가 없다. 맞춤법이 다르고 의미도 완전히 다르므로 혼동해서는 안 된다"고 명확히 판단 — 듣고 받아쓰는 게 아니라 이미 쓰인 글을 감수하는 이 도구의 실제 용도상, 이 두 쌍은 노이즈만 크고 실제 혼동 위험은 낮다고 판단해 목록에서 제외(`common_errors.py`). 나머지 제57항 쌍(가름/갈음, 반드시/반듯이, 마치다/맞히다 등)은 당시 그대로 유지 — 이 두 쌍만 특정해서 제외해 달라는 요청이었음.
  3. **"호출받다"(명사+받다 생산적 파생) — 판단 보류**: 사용자가 "PDF 참고"라고 답함. 원본 자료의 세부 판단 기준은 이 세션에 없어, 문서를 다시 공유받아야 처리 가능 — §22에서 처리됨.
- **검증**: 확신 있는 버그 8건 + 사용자 확인 후 처리 2건 전부 수정 확인, 회귀 테스트 11건 추가, 전체 53개 테스트 통과.

## 22. "받다" 동작성 판단 — 교육자료 재확인 후 처리 (2026-07-17)

§21에서 보류해 둔 "명사+받다"(예: 호출받다) 판단을 위해, 사용자가 원본 번역가 교육자료(PDF, "동사/접사 구분법" 단원)를 다시 공유해 확인함.

- **핵심 규칙(자료 내용을 정리한 것)**: "받다"가 구체적인 사물 명사(상, 만점 등 — 손으로 건네받을 수 있는 것) 뒤에 오면 "받다"는 독립된 동사이므로 띄어 쓴다. 반대로 동작성 명사(호출, 사랑, 상처 등 — 어떤 행위·작용을 나타내는 명사) 뒤에 오면 "받다"는 접사로 붙는다. 이건 앞서 이미 다룬 시키다/당하다/하다/되다와 같은 계열의 판단 기준이다.
- **구현**: "동작성 명사+받다" 조합(호출받다, 사랑받다, 상처받다 등)은 그 조합 자체가 개별 표제어로 사전에 등재되어 있지 않은 경우가 많아(교육자료 예시 단어들도 확인해보니 실제로 그랬음) 사전 등재 여부로는 판단할 수 없다. 대신 "명사+하다"가 사전에 등재되어 있는지로 동작성을 판단하는 `_is_action_noun()`을 추가 — 동작성 명사는 거의 항상 "하다"를 붙여 그 행위 자체를 가리키는 동사를 만들 수 있기 때문("호출하다", "사랑하다" 등은 있지만 "상"은 "하다"를 붙일 수 없음). `_protect_unfounded_respacing()`에 연동.
- **검증**: "호출받다"/"사랑받다"/"상처받다"는 더 이상 플래그되지 않고, "상을 받다"/"만점을 받다"(구체적 사물 명사)는 원래대로 영향 없음을 확인. 회귀 테스트 2건 추가, 전체 55개 테스트 통과.
- **"스트레스받다" 추가 규칙 확인 후 해결 (구현 완료)**: 위에서 남겨뒀던 빈칸 조건을, 사용자가 관련 구글 문서를 공유해 확인함 — **동작성이 없어도 피동 의미(누군가·무언가로부터 그 상태를 겪게 됨)가 있으면 접사로 붙인다**는 추가 규칙. "스트레스"는 "스트레스하다"라는 말 자체가 없어 `_is_action_noun()`으로는 못 걸러내지만, 피동 의미가 있는 대표 사례라 `_PASSIVE_ONLY_BATDA_NOUNS`(현재 "스트레스" 1건)라는 별도 목록으로 관리한다 — "피동 의미가 있다"는 사전 API로 기계적으로 확인할 방법이 없어, common_errors.py의 다른 목록들처럼 검증된 사례를 하나씩 추가하는 방식을 택함. 회귀 테스트 1건 추가, 전체 56개 테스트 통과.
- **번역가 교육자료 종합 재검토 (2026-07-17)**: 사용자가 "이 구글 문서(우리말 표기 원칙 통합본, PDF 4종보다 훨씬 포괄적)의 모든 내용이 중요하니 다 기억해 달라"고 요청함. 원문을 그대로 옮기는 대신, 이 프로젝트 관점에서 재정리한 `번역가_교육자료_요약.md`(신규)를 만들어 각 규칙마다 [구현됨]/[범위 밖]/[백로그 후보]로 분류해 기록함 — 새로 발견된 백로그 후보는 "시키다/당하다/하다/되다/드리다"에도 "받다"와 같은 동작성/피동성 판별 확장, "못 하다/못하다"·"잘못하다"류("안되다/안 되다"와 동일 구조), 순서성 의존명사(제-/층/대), 의존명사 "뿐"/"맨" 등. 나머지 대부분(외래어 표기 세부규칙, 문장부호, 단위 변환, 번역투/전문용어)은 이미 PRD에 범위 밖으로 명시된 항목과 그대로 일치함을 재확인.
  - **후속(같은 날)**: 사용자가 구글 문서 원문 전체를 직접 붙여넣어 훨씬 상세한 내용(동사/접사 구분법의 실제 검증된 정답 사례들, "명사+명사+하다" 3단계 판단, 종결어미 세부, "대로"/"-ㄹ걸" 등)을 추가로 확인 — `번역가_교육자료_요약.md`를 대폭 보강함. 자료의 "요오드→아이오딘" 흔한 오류 항목은 실시간으로 표준국어대사전에 직접 조회해보니 "요오드"도 정상 표제어로(비표준 안내 없이) 등재되어 있어 자료 내용과 실시간 사전 조회 결과가 달랐음 — "실시간 사전 데이터가 항상 우선" 원칙에 따라 추정으로 코드에 반영하지 않고 확인 필요 상태로 남김(자료를 맹신하지 않고 항상 재검증한 사례).
  - **정정(같은 날)**: 사용자가 "우리말샘에 '표준 용어는 아이오딘이다'라고 명기되어 있다"고 재지적 — 실제로 표준국어대사전(stdict)엔 이 안내가 없지만 우리말샘(opendict)에는 있었는데, 제 확인 스크립트가 stdict만 보고 opendict은 제대로 안 봐서 놓쳤음. 이 재확인으로 **두 가지 실제 코드 버그**를 발견해 수정함:
    1. **`_opendict_item_is_standard()`가 "규범 표기는"만 확인하고 "표준 용어는"(화학·의학 등 전문 용어에 쓰는 다른 문구)은 놓치고 있었음** — 두 문구 모두 확인하도록 수정.
    2. **`word_exists()`가 표준국어대사전에 표제어가 있으면 곧바로 True를 반환해, 우리말샘에만 추가된 최신 비표준 안내를 아예 확인하지 않고 있었음** — 표준국어대사전 등재 여부와 무관하게 우리말샘의 비표준 안내도 항상 확인하도록 수정.
  - **`correct_nonstandard_terms()`(engine.py, 신규)**: 위 수정으로 확인 가능해진 "우리말샘이 명시한 비표준 표기"를 실시간으로 조회해 자동 교정하는 세 번째 교정 경로 추가(`correct_always_wrong`의 정적 목록, `correct_loanwords`의 kornorms에 이은 것) — "요오드"는 kornorms엔 오히려 정답으로 등재되어 있어 correct_loanwords로는 못 잡고, 우리말샘 자체의 표준화 안내에서만 확인되는 사례라 새 경로가 필요했음. `dictionary.py`의 `standard_term_replacement()`가 "규범 표기는/표준 용어는 'X'이다" 문구에서 정규식으로 X를 추출.
  - **구현 중 발견한 동형이의어 함정(수정 완료)**: "집"(거처, 표준)과 "집"(즙의 옛 표기, 비표준)이 같은 표제어를 공유하는데, 초기 구현이 첫 번째로 검색된 동형이의어만 보고 "집" 전체를 비표준으로 오판해 "그리고 나서 집에 갔다"가 "그러고 나서 즙에 갔다"로 잘못 고쳐지는 사고가 남(§20의 "두강"/"그다리" 동형이의어 충돌과 같은 종류의 함정). `word_exists()`/`standard_term_replacement()` 둘 다, 같은 표제어를 공유하는 동형이의어 중 **하나라도 표준이면 전체를 비표준으로 단정하지 않도록** 수정.
  - **또 다른 실제 버그 발견(수정 완료)**: "요오드가"→"아이오딘가"처럼, 단어를 치환한 뒤 받침 유무가 달라지는데 뒤따르는 조사(이/가, 은/는, 을/를, 과/와)를 안 바꿔 비문이 생기는 문제를 검증 중 발견 — 이미 배포되어 있던 `correct_discriminatory_terms()`에도 같은 버그가 있었음("벙어리가"→"언어장애인가"). `_apply_replacements()`(공통 헬퍼)에 한글 유니코드 받침 판별(`_has_batchim`)과 조사 짝 자동 교체(`_matching_particle_allomorph`) 추가 — "으로/로"는 ㄹ받침 예외가 있어 확신이 없어 제외.
  - **검증**: 요오드/아이오딘/초코렛/집/쉴더병/노천카페 전부 정상 확인, 회귀 테스트 4건 추가, 전체 60개 테스트 통과.

## 23. 어미 처리 재설계 — "kiwi는 참고일 뿐, 사전 표제어가 기준" (2026-07-17)

사용자가 "이 프로그램이 어미를 잘 처리하지 못하는 문제가 심각하다"고 지적하고, 개선 방향으로 "kiwi는 참고일 뿐, 사전의 표제어와 용례를 기준으로 해야 한다"는 원칙을 명확히 제시함.

- **기존 구조의 근본 문제**: `check_spacing()`은 kiwi.space()의 통계적 제안을 원문과 diff해서 그 차이를 사후에 하나씩 막는 방식이었다(존대 보조사 "요", 종결어미(EF) 태그, 조건 어미 등 지금까지 추가한 예외가 전부 이런 패치였음). 반대로 `_mechanical_respace()`(조사 처리)는 kiwi의 제안을 아예 참고하지 않고 형태소 태그만으로 직접 판단하는 방식이라 지금까지 버그가 거의 없었다. "시간이 없다잖나"("없다고 하지 않나"의 압축)가 계속 못 잡히던 근본 원인은 전자의 한계 — "잖"이라는 한 글자에 여러 형태소가 압축되면서 kiwi의 재구성이 원문과 어긋나기 때문이었다.
- **검증(구현 전)**: 표준국어대사전/우리말샘이 실제로 "-잖다", "-거든", "-ㄹ걸" 같은 압축·구어체 어미를 앞에 하이픈을 붙인 형태로 하나의 표제어로 등재해 두고 있음을 실시간 조회로 확인 — 이 하이픈 표기 관례(어미·조사·접사가 공통으로 씀, 앞말에 붙는다는 뜻)를 근거로 삼을 수 있다는 걸 먼저 검증한 뒤 구현에 들어감("검증표 먼저, 코드는 나중" 원칙).
- **구현 1 — `registered_ending()`(dictionary.py, 신규)**: candidate가 "-candidate" 형태로 사전에 등재되어 있으면 그 표제어를 돌려준다. `_protect_unfounded_respacing()`에서 기존에 "종결어미(EF)만" 보호하던 걸 "제41항 부착 태그 전체(`_ATTACH_TAGS`: EC 포함) 또는 사전에 등재된 어미·접사 표제어"로 확장 — kiwi의 태그 분류가 아니라 사전 표제어 자체를 최종 근거로 삼는다.
- **구현 2 — `_tokenization_unstable_near()`(engine.py, 신규)**: "없다잖나"는 kiwi가 "하다"를 통째로 생략해 길이 0인 유령 토큰까지 만들어내는 더 깊은 압축이라, 구현 1만으로는 못 잡았다(위치 기반 토큰 검색 자체가 엉뚱한 토큰을 짚어옴). 공백 삽입 지점 주변에 길이 0인 토큰이 있으면 — kiwi 스스로도 이 구간의 형태소 경계를 확신하지 못한다는 신호이므로 — kiwi의 공백 제안을 검증하지 않고 아예 원문을 보존하도록 추가.
- **회귀 발견 및 수정**: 처음엔 "길이 0" 대신 "위치 겹침(overlap)"까지 신호로 썼다가, "됩니다"(되+ㅂ니다)처럼 어간과 어미가 받침 하나를 공유해 위치가 겹치는 지극히 정상적인 활용까지 오탐지해 "그러면 안됩니다"의 정당한 "안 됩니다" 분리 제안(§20)이 막혀버리는 회귀가 생김 — 위치 겹침 신호는 제거하고 길이 0(형태소가 완전히 생략됨)만 이례적인 신호로 남김.
- **검증**: "시간이 없다잖나"는 더 이상 잘못 갈라지지 않고, "그러면 안됩니다"→"안 됩니다" 분리 제안은 그대로 정상 동작함을 확인. 회귀 테스트 2건 추가, 전체 62개 테스트 통과.

## 24. 제출 전 점검 — 저장 실패와 교정 실패 분리 (2026-07-17)

과제 제출 루브릭(보안 점검/백엔드 동작 일치/서비스 직관성) 기준으로 프로젝트를 검토하던 중, 실제 백엔드 동작이 의도와 어긋나는 지점을 하나 발견함.

- **문제**: `api.py`의 `/api/correct`가 `store.save_report()`(Supabase 저장)를 예외 처리 없이 호출하고 있었다. 한국어 교정 자체(핵심 로직)는 이미 성공했는데도, 저장 단계에서 실패하면(Supabase 무료 티어 일시정지, 네트워크 지연 등 — DEPLOY.md에 이미 명시된 위험) 예외가 그대로 올라가 교정 결과 전체가 사라지고 사용자는 "서버 오류"만 보게 됨. "의도한 동작"(교정하고 저장한다)과 실제 동작(저장 실패 시 교정도 실패한 것처럼 보임)이 어긋나는 지점.
- **조사**: Supabase의 실제 비활성 정책을 웹 검색으로 확인 — 활동 판단 기준은 실제 DB 쿼리이고, 일단 일시정지되면 요청이 온다고 자동으로 재개되지 않으며 대시보드에서 사람이 직접 "Resume project"를 눌러야 함(90일 지나면 복구 불가). 사용자가 매일 직접 사용하기로 해서 "비활성으로 인한 정지"라는 원인 자체는 사실상 해결됐지만, 채점 시점을 사용자가 통제할 수 없다는 점과 네트워크 지연 등 다른 일시적 실패 원인은 남아 있어, 코드 쪽 완화가 여전히 필요하다고 판단해 진행.
- **구현**: `store.save_report()` 호출을 `try/except (RuntimeError, requests.RequestException)`로 감싸 실패 시 `report_id = None`으로 처리 — 교정 결과(`corrected_srt`/`flags`/`applied_log`)는 그대로 응답한다. 프론트(`static/index.html`)도 `data.id`가 없으면 공유 링크 대신 "저장에 실패해 공유 링크를 만들지 못했다"는 안내만 보여주고, 교정 결과 자체는 정상적으로 렌더링하도록 수정.
- **검증**: `store.save_report`를 `RuntimeError`(환경변수 누락)와 `requests.exceptions.Timeout`(네트워크 지연) 양쪽으로 모의 실패시켜, 두 경우 모두 `id=None`이면서도 `corrected_srt`/`flags`(4건)/`applied_log`(6건)는 정상 반환됨을 직접 확인. 정상 경로(저장 성공)도 회귀 없이 그대로 동작함을 재확인.

## 30. 표준국어대사전 "전 용어"(옛 용어) 동적 규칙 — 자동교정/플래그 안전 분기 (2026-07-25)

### 배경
표준국어대사전은 표준 용어가 바뀐 옛 표기를 뜻풀이 끝에 **"'X'의 전 용어."**로 안내한다(X = 현재 표준 용어). 지금까지 이 중 "간질→뇌전증"만 `common_errors.py`의 `DISCRIMINATORY_TERMS`에 하드코딩해 자동 교정했는데, 이는 (1) 정적 목록이라 사전 개정을 못 따라가고 (2) "간질"의 동음이의 위험을 무시한 방식이었다. 이를 실시간 사전 조회 기반 동적 규칙으로 교체했다.

### 검증된 표지 형식 (2026-07-25 표준국어대사전 API 직접 조회)
- 대상 용어는 통낫표(`‘’`)로 감싸고 곧바로 `의 전 용어`가 온다. 추출 정규식: `[‘']([^’']+)[’']의\s*전\s*용어` (곧은 따옴표 fallback 포함), group(1)이 현재 표준 용어.
  - `간질` 4번째 뜻: `‘뇌전증’의 전 용어.` → 대상 = 뇌전증
  - `정신분열증`(표제어 `정신^분열증`) 유일한 뜻: `‘조현병’의 전 용어.` → 대상 = 조현병
- **"낮잡아/속되게 이르는 말"은 이 표지가 아니다** — `문둥이`("‘나환자’를 낮잡아 이르는 말"), `지랄병`("‘간질’을 속되게 이르는 말")은 매칭되지 않음(정확히 "전 용어"만 매칭). 확인 완료.
- 현재 표준 용어(`뇌전증`, `조현병`)에는 이 표지가 없어 절대 플래그되지 않음. 확인 완료.

### 동음이의(polysemy) 위험 — 자동교정 vs 플래그 안전 결정
`간질`은 표준국어대사전에 4개 뜻이 있다: (1) '간질거리다' 어근 (2) 곤충(간디스토마) (3) 조직(간질 조직) (4) '뇌전증'의 전 용어. **오직 (4)만 옛 용어**이므로, "간질"을 무조건 "뇌전증"으로 바꾸면 곤충/조직/간지럽힘 뜻을 훼손한다. 안전 규칙(사용자 결정):
- **모든 뜻이 "전 용어" 뜻인 단어** (예: 정신분열증 — 뜻이 하나뿐이고 그것이 옛 용어) → 문맥과 무관하게 정답이 하나이므로 **자동 교정**.
- **"전 용어" 뜻 외에 다른 뜻도 있는 동음이의어** (예: 간질) → **자동 교정하지 않고 플래그만** 남긴다. `suggested_fix`에 현재 표준 용어를, 사유에 나머지 뜻들을 실어 사람이 문맥으로 판단하게 한다. 텍스트만으로 어느 뜻인지 자동 판별하는 것은 확률적 추정이라 이 프로젝트가 금지하는 방식이므로(문맥 기반 의미 판별 시도 안 함), 플래그가 안전한 fallback이다.

### 변경 파일
- `dictionary.py`: `former_term_lookup(word)` 추가 — `search_stdict`로 모든 채널 항목·뜻을 모아 "전 용어" 표지를 탐지, `{"target", "ambiguous", "other_meanings"}` 또는 None 반환. 조회/파싱 실패는 None으로 흡수(파이프라인 중단 방지). `search_stdict`가 이미 lru_cache이고, 이 함수에도 lru_cache를 달아 반복 토큰의 재조회를 막음.
- `engine.py`: `correct_former_terms(index, text)` 추가 후 `correct_entries()` 파이프라인의 표준화 교정 구간(비지정·to_standard 화자만; protect/assist는 기존대로 건너뜀)에 연결. 자동교정은 `applied_log`, 플래그는 `flags`로. **kiwi가 "정신분열증"을 "정신"+"분열증"으로 쪼개는 문제**(그리고 "분열증" 단독도 옛 용어라 "정신조현병" 오교정이 남) 때문에, 단순 토큰별 조회가 아니라 공백 없이 이어진 명사 토큰 구간에서 **긴 결합부터 그리디 매칭**해 다형태소 옛 용어를 한 단위로 처리한다. 치환은 토큰 경계 안전한 기존 `_apply_replacements` 사용.
- `common_errors.py`: `DISCRIMINATORY_TERMS`에서 `"간질": "뇌전증"` **제거**(동음이의어라 자동 교체 부적절 → 새 동적 규칙이 플래그로 처리). 나머지 차별어 항목은 그대로.
- `tests/test_former_terms.py`(신규) + `test_engine.py`의 간질 테스트를 새 동작(자동교체 안 함)으로 수정.

## 36. 띄어쓰기 기준 선택(원칙/허용) (2026-08-02)

사용자 요청: 웹 페이지에서 띄어쓰기를 원칙으로 할지 허용으로 할지 고를 수 있게 하되, **한 작품 안에 두 기준이 섞이면 안 된다**. 상세 설계는 `PRD.md` §13.

- **왜 필요했나**: 제47항의 원칙(띄어 씀)과 허용(붙여 씀)은 둘 다 맞는 표기다. 기존 엔진은 원칙만 지원해, 붙여 쓰기로 통일한 작품을 넣으면 전부 띄어 써 버렸다. 어느 쪽이 맞느냐가 아니라 **작품이 고르는 문제**라는 점이 핵심이다.
- **구조**: `correct_aux_verb_spacing`의 판정 로직을 `_aux_verb_spacing(text, mode)`로 옮기고, 기존 함수는 원칙 전용 얇은 래퍼로 남겼다(기존 호출부·테스트 8건이 그대로 통과). 대상 구간(패턴 1·2)은 두 기준이 완전히 동일하고, 간격을 넣느냐 빼느냐만 갈린다 — 그래서 탐지 로직을 복제하지 않고 `edits`에 치환 문자열(`" "` 또는 `""`)을 함께 담는 방식으로 한 곳에서 처리한다.
- **혼용 방지**: 기준은 `correct_entries(spacing_mode=...)`에서 한 번 정규화해 모든 줄에 같은 값을 넘긴다. 줄 단위로 다른 기준을 줄 수 있는 경로 자체를 만들지 않았다.
- **붙임 불가 구간**(본용언이 3음절 이상 합성어, 의존명사+하다 조합이 사전에 없음)은 허용 기준에서도 띄어 쓴다. 조용히 띄우면 사용자가 "허용을 골랐는데 왜 섞였지"로 오해하므로, 자동 교정 로그에 `[붙임 불가] ... -> 허용 기준에서도 띄어 씀` 사유를 남긴다(사용자 결정).
- **함정 1 — 안내문의 어절이 잘림**: 토큰 경계가 형태소 단위라 구간 텍스트를 그대로 쓰면 `'덤벼들어 보'`처럼 어절 중간에서 끊긴다. `_surface_span()`으로 양쪽 어절 경계까지 넓혀 `'덤벼들어 보아라'`로 보여준다.
- **함정 2 — 붙임 근거 확인 순서**: 패턴 2에서 원래 코드는 "일단 edits에 넣고 사전에 없으면 discard"였다. 허용 기준에서는 붙임 불가 **사유를 남겨야** 하므로 사전 확인을 먼저 하도록 순서를 바꿨다(원칙 기준의 결과는 동일).
- **노출**: `/api/correct`의 `spacing_mode` Form, `main.py --spacing principle|allowance`(모르는 값이면 원칙으로 진행한다고 알림), `static/index.html` 라디오 + "한 작품 안에서는 한쪽으로 통일" 안내 문구.
- **검증**: pytest 160건 통과(신규 10건). `examples/sample.srt` 두 기준 비교 결과 차이는 `할 만하다`/`할만하다` 한 줄뿐, 자동교정·플래그 3건은 동일. FastAPI `TestClient`로 `spacing_mode` 전달 확인(principle/allowance/알 수 없는 값 → 원칙). 허용 기준으로 붙인 형태가 `check_spacing`에서 다시 플래그되지 않는 것도 테스트로 고정.
- **범위**: 제47항 보조 용언만(사용자 결정). ~~제46항·제50항은 붙임/띄움 판정 로직 자체가 없어~~ **정정(2026-08-02, §37 참고)**: 제50항은 `_TERM_COMPOUND_TAGS`로 붙여 쓴 형태를 보호하는 로직이 이미 있었다. 없던 것은 기준에 맞춰 통일하는 쪽이다. 제49항·제50항은 §37에서 혼용 감지로 처리했고, 제46항은 여전히 미착수다.

## 37. 고유명사·전문 용어 띄어쓰기 혼용 감지 (2026-08-02)

§36(제47항 원칙/허용 선택) 직후, 사용자가 "제49항·제50항 규칙도 이미 알려줬는데 빠지지 않았느냐"고 지적해 확인한 결과 실제로 빠져 있었다. 규칙 정리와 설계는 `PRD.md` §14.

- **내가 틀렸던 것**: §36에서 "제50항은 붙임/띄움 판정 로직 자체가 없다"고 적었는데 부정확했다. `_TERM_COMPOUND_TAGS`가 이미 있고 **붙여 쓴 전문 용어·고유명사를 보호**한다(kiwi가 쪼개자는 제안을 되돌림). 없던 것은 "기준에 맞춰 통일"하는 쪽이다. `PRD.md` §13과 이 로그 §36의 해당 줄을 정정했다.
- **실제 구멍**: 한 작품에 `만성 골수성 백혈병`과 `만성골수성백혈병`이 섞여 있어도 둘 다 통과했다. 사용자가 요구한 "한 작품 안에 섞이면 안 됨"이 제47항에서만 지켜지고 있었다.
- **왜 제47항처럼 자동 통일하지 않았나**: 붙이려면 어디까지가 한 용어인지 알아야 하는데(고유명사는 의미 단위, 전문 용어는 전체), 그 경계는 사전에 없고 문맥 추측이 필요하다. §5 원칙에 정면으로 걸려 자동 통일 대신 **혼용 감지 플래그**로 결정(사용자 선택).
- **판정은 문자열 비교만**: 공백을 지운 문자열이 같은데 표면형이 다르면 혼용. 추측이 없다.
- **함정 1 — 최대 구간만으로는 안 짝지어짐**: `만성 골수성 백혈병 진단`과 `만성골수성백혈병 치료`는 뒤에 붙는 말이 달라 최대 구간의 키가 서로 다르다. 부분 구간까지 후보로 내고, 같은 혼용이 여러 길이로 걸리면 가장 긴 것만 남기는 방식으로 해결.
- **함정 2 — 태그가 모자라 구간이 끊김**: `강력팀`의 `강력`은 XR(어근), `골수성`의 `성`은 XSN(접미사)이라 `_TERM_COMPOUND_TAGS`만으로는 구간이 중간에 끊겨 짝을 못 찾았다. 혼용 감지 전용으로 `_TERM_RUN_TAGS = _TERM_COMPOUND_TAGS | {XR, XSN}`를 따로 뒀다 — 기존 보호 로직의 태그 집합은 건드리지 않았다.
- **함정 3 — 다수결이 규정을 어기는 표기를 제안**: `세종대로`/`세종 대로`가 1회씩이면 단순 다수결·동률 규칙으로는 `세종 대로`(규정 위반)를 통일 후보로 제안하게 된다. 거리 이름의 `대로/로/가`를 띄어 쓴 표기를 후보 우선순위에서 맨 뒤로 미뤄 해결(`_violates_street_name_rule`). 이 형태를 그 자체로 오류 플래그하지는 않는다.
- **하지 않은 것**: `부분만 붙임` 판정(전문 용어에서 금지, 고유명사에서 허용 — 어느 쪽인지 아는 것 자체가 추측), 제46항.
- **검증**: pytest 168건 통과(신규 8건). `examples/sample.srt`는 결과·리포트 모두 이전과 완전히 동일 — 새 검사가 기존 문서에 노이즈를 더하지 않음을 확인했다.
- **부수적으로 발견한 기존 버그(미수정)**: `개나리길 입구에서 봐` -> `개나리길 입구에 서 봐`. 조사 `에서`를 `에`+`서다`로 갈라놓는 과교정으로, 이번 변경과 무관한 기존 동작이다. `docs/BACKLOG.md`에 등록했다.

## 38. 웹 서버 실사용 검증 중 발견 — 규정 위반 띄어쓰기 제안 (2026-08-02)

§37 직후, 실행 중인 웹 서버(`/api/correct`)에 샘플을 실제로 올려 검증하다가 발견했다. 코드/테스트만으로는 안 보였고 결과 화면을 사람 눈으로 읽어야 드러나는 종류였다.

- **증상**: `만성골수성백혈병 치료는 길다`에 대해 `check_spacing`이 `만성골수성 백혈병 치료는 길다`를 제안했다. 전문 용어는 붙이려면 전부 붙여야 하므로(제50항) 이건 **규정에 어긋나는 부분 붙임을 사람에게 권하는** 제안이다. `마포경찰서 강력팀이` -> `마포경찰서 강력 팀이`도 같은 유형. 게다가 §37의 혼용 플래그와 같은 줄에 서로 모순되는 제안이 동시에 떴다.
- **원인**: `_protect_unfounded_respacing`의 전문 용어 보호가 `_TERM_COMPOUND_TAGS`(NNG/NNP/SN/SL/XPN/NR)만 봐서, 어근(XR: '강력')과 명사 파생 접미사(XSN: '골수성'의 '성') 경계에 공백을 끼워 넣자는 제안이 보호를 통과했다. §37에서 혼용 후보 구간이 끊기던 것과 **같은 태그 구멍**이다.
- **수정**: 그 판정만 `_TERM_RUN_TAGS`(= `_TERM_COMPOUND_TAGS` + XR + XSN)로 넓혔다. XR·XSN은 앞말과 항상 붙는 형태소라 그 자리에 공백이 들어갈 근거가 애초에 없다.
- **검증**: pytest 168건 통과(기존 테스트 전부 유지 — 넓힌 보호가 정당한 교정을 막지 않음). 혼용 샘플의 확인 필요 항목이 5건에서 3건으로 줄었고(부분 붙임 제안 2건 제거), 남은 3건은 전부 혼용 플래그다. `examples/sample.srt` 결과·로그·플래그는 이전과 동일.
- **교훈**: 테스트가 전부 통과해도 "사람에게 무엇을 보여주는가"는 실제로 화면을 봐야 안다. `PRD.md`의 "실제 텍스트로 돌려서 검증한다" 관례에 **결과 화면을 규정과 대조하는 것**까지 포함할 것.

## 39. 문서 전체 사투리 설정 — 일반 글용 (2026-08-02)

사용자 질문에서 출발: "일반 글은 글 전체가 사투리일 수 있다. 박경리 '토지'를 현대 표준어로 바꾸는 데도 이 교정기가 쓰였으면 한다."

- **확인한 사실**: 사투리 처리는 화자 이름이 있어야만 걸렸다(`resolve_dialect_mode`가 `speaker`를 `dialect_map`에서 찾지 못하면 `(None, None)`). 화자는 자막의 `[이름]` 표기에서 뽑으므로, **일반 글에서는 사투리 기능이 아예 동작하지 않았다.** 화면에는 "화자별 사투리 설정"만 있어서 이 사실이 드러나지 않았다.
- **변경**: `resolve_dialect_mode(..., document_region, document_mode)` — 화자별 지정이 우선이고, 없으면 문서 전체 설정으로 내려간다. `correct_entries(dialect_region=, dialect_mode=)`로 받아 모든 줄에 같은 값을 넘긴다.
- **기본값은 protect 유지**: 지역만 고르고 모드를 안 주면 보호다. 글 전체를 말없이 표준어로 바꾸는 것이 기본이 되면 안 된다.
- **지원하지 않는 지역명은 무시**한다(API·CLI 모두). 오타 하나로 글 전체가 엉뚱한 기준으로 처리되는 것보다 미지정이 안전하다.
- **노출**: `/api/correct`의 `dialect_region`·`dialect_mode` Form, `main.py --dialect-region/--dialect-mode`, 웹 UI 사투리 그룹 맨 위의 "문서 전체" 드롭다운 2개. 옵션 요약 줄에도 반영("문서 전체 경상도 사투리").
- **검증**: pytest 176건 통과(신규 8건). 화자 표기가 전혀 없는 `.txt`를 실제 서버에 올려 확인 — 설정 없으면 원문 그대로, `경상도`+`to_standard`면 "이거 아이가 마이시 좋다" -> "이거 그래 많이 좋다", 없는 지역명이면 원문 그대로.
- **알려진 한계(그대로 남음)**: 변환은 `convert_dialect()` 정적 매핑에 의존한다. 같은 검증에서 "밥은 뭇나 안 뭇나"는 바뀌지 않았다. 지역어 종합정보 API가 살아나기 전까지 문학 사투리 전면 표준어화는 부분적으로만 된다.
- **다음**: 사용 목적(자막/일반 글)에 따라 세부 설정을 갈라 보여주는 UI. 자막 쪽에는 글자 수·줄 수 검사(미구현)가 들어가야 칸이 채워진다.

## 41. 자막 구두점 규칙 3건 (2026-08-02)

사용자가 자막 모드 구두점 규칙을 직접 지정했다. 셋 다 자막 관례상 정답이 하나뿐이라 확인 플래그가 아니라 자동 교정이다. 일반 글 모드에는 하나도 적용하지 않는다 — "사용 목적을 자막으로 고른 경우에 한해"라는 조건이 이 대비로 구현된다.

1. **각 행 끝 마침표 생략** — 이미 구현돼 있었다(`correct_subtitle_final_period`, 커밋 `91989e4`에서 줄 단위로 보강). 실측으로 확인만 하고 손대지 않았다.
2. **행 중간 문장 사이 마침표 → 쉼표** — 기존 `check_subtitle_internal_period`(확인 플래그)를 `correct_subtitle_internal_period`(자동 교정)로 승격하고 옛 함수는 지웠다. 플래그였던 이유는 "문장 경계 판단은 사람이"였지만, 사용자가 자막에서는 이 자리에 쉼표를 쓰는 것이 확정 규칙이라고 지정했다.
3. **말줄임표 = 온점 세 개** — 신규 `correct_subtitle_ellipsis`. 말줄임표 문자(`…`, 연속이면 하나로)와 온점 네 개 이상(`......`)만 `...`로 바꾼다. 온점 하나·둘은 건드리지 않는다(하나는 마침표, 둘은 말줄임표로 단정할 근거 없음).

- **순서가 중요하다**: 말줄임표 통일 → 중간 마침표 → 줄 끝 마침표. 말줄임표를 먼저 `...`로 만들어야 뒤의 마침표 규칙이 `_is_sentence_period()`로 그것을 걸러 낼 수 있고, 중간 마침표를 쉼표로 바꾼 뒤 줄 끝을 지워야 `"보여 주세요. 궁금해요."`가 `"보여 주세요, 궁금해요"`로 한 번에 정리된다.
- **함정 — 편집 중 블록 중복**: 새 함수를 끼워 넣다가 `correct_subtitle_bracket_spacing`과 `_BRACKET_CLOSE_RESPACE_RE`가 통째로 두 번 들어갔다. import는 통과해서(뒤 정의가 앞을 덮어씀) 조용히 넘어갈 뻔했다. `grep -n "^def "`로 정의 목록을 확인해 잡았다. **큰 파일에 함수를 삽입한 뒤에는 정의 중복부터 확인할 것.**
- **검증**: pytest 195건 통과(신규 20건, `tests/test_subtitle_punctuation.py`). 기존 테스트 2건은 플래그를 기대하고 있어 자동 교정 기대값으로 고쳤다. 일반 글 모드 회귀도 함께 고정했다(`"보여 주세요. 궁금해요…"`가 그대로 유지되는지).
- **미결**: 인용부호 규칙(인용은 작은따옴표, 큰따옴표는 화면자막 등에만). 큰따옴표를 작은따옴표로 바꾸는 것 자체는 형태만 보면 되지만, "화면자막 등 기타 요소"라는 예외는 그 따옴표가 화면에 뜬 글자를 옮긴 것인지 인용인지 알아야 갈려 사전·형태 어디에도 근거가 없다. 사용자 결정 대기.

## 42. 자막 편집 표지 설정 + 줄 단위 파이프라인 분리 (2026-08-02)

§41 인용부호 논의에서 이어짐. 사용자가 "자막에는 사용자가 지정해야 하는 기술적 표지가 있고, 업계 공통 규칙이 없으니 그때그때 설정으로 받아야 안전하다"고 정리했다. 설계는 `PRD.md` §16.

- **§41의 미결이 여기서 풀렸다**: 큰따옴표를 작은따옴표로 바꿀지 물었던 문제의 답이 "따옴표는 화면자막 표지이므로 교정 대상이 아니다"였다. 표기를 바꾸는 규칙이 아니라 **제외 규칙**이 필요했던 것이다.
- **구조 변경(순수 이동)**: 화면자막을 "감싸인 구간만" 제외하려면 한 줄을 여러 조각으로 쪼개 일부만 교정해야 하는데, 파이프라인이 `correct_entries()` 반복문 안에 박혀 있어 그렇게 부를 수 없었다. 본문을 `_correct_line(index, text, doc_type, spacing_mode)`으로 그대로 떼어냈다. **이동 직후 195건이 그대로 통과하는 것을 먼저 확인한 뒤** 표지 로직을 얹었다.
- **함정 — 들여쓰기**: 반복문 안(8칸)에서 떼어낸 블록을 그대로 붙이면 `IndentationError`가 난다. `textwrap.dedent` 후 4칸으로 다시 넣었다. 편집이 꼬였을 때는 `git checkout -- <파일>`로 되돌리고 다시 하는 편이 빠르다(이번에도 그렇게 했다).
- **플래그를 줄 전체로 되돌리는 이유**: 구간 단위 교정의 플래그를 그대로 두면 `suggested_fix`가 조각이 된다. `apply_report_fixes()`는 `entry.text = fix`로 줄 전체를 덮어쓰므로, 조각이 들어가면 나머지 대사가 지워진다. 이 위험을 테스트로 고정했다(`test_flag_suggestion_covers_the_whole_line`).
- **검증**: pytest 208건 통과(신규 13건). 실제 서버 업로드로 확인 — 표지를 지정하면 `"초코렛. 세일중"`은 그대로, 표지 밖 `초코렛`은 `초콜릿`으로, `|` 앞 마침표는 줄 끝으로 보고 제거. 표지를 지정하지 않으면 예전처럼 전부 교정한다.

## 43. '말라 그래' 오교정 수정 + 화자명·어조 부호 설정 (2026-08-02)

사용자가 실사용에서 오교정 1건을 발견하고, 자막 편집 표지 설정에 두 항목을 더 요청했다.

- **오교정**: `지랄하시지 말라 그래.` -> `지랄하시지 말라, 그래`. 이건 "말라고 해"의 준말이라 '그래'가 감탄사가 아니라 인용을 받는 서술어인데, 쉼표가 들어가면 뜻이 갈라진다.
  - **원인**: kiwi는 문장부호가 붙어야("말라 그래.") 이 '그래'를 IC로 태깅한다. 마침표 없이 넣으면 VA-I+EF라 재현되지 않았다 — **오교정 재현은 사용자가 본 원문 그대로(문장부호 포함) 넣어야 한다.** 처음에 마침표를 빼고 넣어 "재현 안 됨"으로 오판할 뻔했다.
  - **수정**: `_is_quoted_command()` — '그래' 바로 앞이 인용 축약 어미(-라/-으라/-자/-냐/-마/-래)면 감탄사 쉼표 규칙을 건너뛴다. 동의의 '그래'("밥 먹자, 그래")와 겹치는 경계가 남지만, 안 넣어서 생기는 손해(사람이 직접 넣음)가 잘못 넣어서 생기는 손해(뜻이 바뀜)보다 작다.
- **화자명·어조 부호 설정**: OTT마다 대괄호와 괄호가 갈린다. `SubtitleMarkers`에 `speaker`·`tone`을 더하고, 하드코딩돼 있던 `correct_subtitle_bracket_spacing`의 `]`를 설정된 닫는 부호로 일반화했다. 한 글자만 적으면 짝을 채우고(`(` -> `()`), 짝 없는 문자는 기본값(대괄호)으로 떨어뜨린다 — 짝이 없으면 어디까지가 화자명인지 정할 수 없다.
  - **기본값은 대괄호 유지**: 지금까지의 동작이 대괄호 기준이라 기본값을 바꾸면 기존 사용자의 결과가 조용히 달라진다.
  - 설정하지 않은 부호는 건드리지 않는다(대괄호 원고에서 괄호까지 손대면 정당한 표기를 망친다).
- **검증**: pytest 218건 통과(신규 10건). 감탄사·호격 쉼표 규칙 자체가 살아 있는지도 회귀로 고정했다(`아이고, 어떻기는` / `먹어, 준희야` / `싫다면, 뭐`).

## 44. 실사용 오탐 2건 해결 — 감탄사 표제어 분할, 근거 없는 분리 제안 (2026-08-02)

`docs/BACKLOG.md` 18·19번을 사용자 요청으로 시험해 둘 다 해결했다.

- **19번(느낌표) — 진단이 어긋나 있었다.** 사용자는 "느낌표가 한 칸 띄워져 플래그됐다"고 보고했는데, kiwi가 느낌표 앞에 공백을 넣는 사례는 400여 조합을 돌려도 0건이었다. 실제 원인은 **감탄사 표제어 분할**이다: `에라이!` -> `에라,이!`, `아싸!` -> `아싸`가 아니라 `아,싸!`. kiwi가 `에라이`(표제어)를 `에라`(IC)+`이`로 쪼갠 분석을 믿고 감탄사 쉼표 규칙이 쉼표를 박았다. 앞 글자가 떨어져 나오니 "느낌표가 띄워진 것"처럼 보인 것이다. **플래그가 아니라 자동 교정이었다는 점에서 더 나빴다.**
  - 수정: `_inside_headword()` — 쉼표를 넣을 자리가 사전 표제어 한 단어 내부면 넣지 않는다. 사전이 kiwi 분석보다 권위 있다는 기존 원칙 그대로다.
- **18번(한짓골) — 검토안이 통과했다.** `_protect_unresolvable_splits()`: 분리로 생기는 조각이 전부 사전으로 설명될 때만 제안을 남긴다. `한짓골에` -> `한` + `짓골에`인데 `짓골`이 사전에 없으므로 취소.
  - **함정 ① 중간 상태 조회**: 삽입 지점 하나만 놓고 좌우를 보면 `먹을수있다`에서 `수있다`를 조회하게 되어 정당한 의존명사 제안이 죽는다. 삽입 지점을 **어절별로 모아 최종 조각 전체**를 봐야 한다.
  - **함정 ② 받침 공유 활용**: `됩니다`는 어간과 어미가 받침을 공유해 표면형으로 자를 수 없다. 이 갈래를 안 만들면 `안 됩니다` 제안이 함께 죽는다(실측에서 테스트 3건이 깨졌다).
  - **함정 ③ 되짚기가 너무 관대하면 규칙이 무력해진다**: 표면형으로 잘라 실패했는데 첫 형태소로 다시 봐주면 `짓골에`가 `짓`(표제어) 때문에 통과해 버린다. 되짚기는 **표면형으로 자를 수 없을 때만** 쓴다.
- **회귀 측정**: pytest 221건 통과, held-out 12/14(85.7%)로 기준선과 동일. 자동 교정(`오늘은 날씨가 좋네요`, `착오가 있었던`)과 정당한 제안(`안 됩니다`, `먹을 수 있다`)이 모두 유지되는 것을 확인했다.

## 45. '에서' 과교정 해결 — 합쳐 읽는 조사 후보가 있으면 갈라놓지 않는다 (2026-08-02)

`docs/BACKLOG.md` 15번. §37 작업 중 부수적으로 발견해 적어 둔 항목이다.

- **증상**: `개나리길 입구에서 봐` -> `개나리길 입구에 서 봐`. **자동 교정**이라 리포트를 봐도 눈에 잘 안 띄고, 대사의 뜻이 바뀐다.
- **원인**: 진짜 중의성이다. kiwi 1순위 분석이 `에`(JKB)+`서`(VV, 서다)+`어`(EC)이고, `_mechanical_respace`의 "조사 뒤는 새 어절" 규칙이 그 분석을 믿고 공백을 넣었다. 그런데 `입구에서 보자`(장소)와 `입구에 서 봐라`(서 있어라) 둘 다 문법적으로 가능하다 — 문맥이 정할 일이지 자동으로 고를 일이 아니다.
- **판정 근거는 kiwi 자신의 대안 분석**: `_kiwi.analyze(어절, top_n=5)`에 같은 자리에서 시작하면서 더 긴 조사 토큰(`에서`)이 있으면 "합쳐 읽는 읽기가 존재한다"는 **사실**이다(확률 비교가 아니다). 있으면 원문 간격을 보존하고 사람 확인에 맡긴다.
- **원문이 이미 띄어 쓰여 있으면 이 판정을 하지 않는다**: `거기에 서 봐`처럼 띄어 쓴 경우에는 합쳐 읽는 후보 자체가 생기지 않는다. 이 함수는 붙어 있는 경우에만 호출한다.
- **회귀 측정**: pytest 224건 통과(신규 2건), held-out 12/14로 기준선 동일. 조사·어미 결합 자동 교정(`오늘은날씨가좋네요` -> `오늘은 날씨가 좋네요`)은 그대로 살아 있다.

## 47. `api.py` 정리 — 업로드 처리 중복 제거 + 리포트 조회 방어 (2026-08-02)

교정 로직은 건드리지 않았다. HTTP 계층의 중복과 빈틈만 정리했다.

- **업로드 검증 일원화**: 확장자 허용 목록·크기 제한·임시 파일 실체화가 `/api/correct`와 `/api/speakers`에 따로 적혀 있었다. `_read_upload()` + `_materialized()` 하나로 합쳤다. 따로 두면 한쪽만 고쳐져 "업로드 화면에서는 막히는데 다른 경로로는 통과한다"가 된다. 부수 효과로 `/api/speakers`도 PDF 30MB 한도를 함께 쓰게 됐다(같은 근거의 같은 규칙이므로 갈라 둘 이유가 없다).
- **`filename`이 없는 업로드**: `Path(file.filename)`이 `None`에 터지던 자리를 `file.filename or ""`로 막았다. 확장자 검사에서 400으로 걸린다.
- **리포트 id 검증**: `/api/reports/{id}`의 id는 PostgREST 필터 문자열(`id=eq.{...}`)에 그대로 들어간다. 쉼표 같은 문자가 섞이면 의도하지 않은 질의가 되므로, 저장할 때 쓰는 형식(uuid4)이 아니면 조회하지 않고 404로 돌려준다.
- **저장소 장애와 "없는 리포트" 구분**: `store.get_report()`가 네트워크 예외를 던지면 스택 트레이스와 함께 500이 나가던 것을 502로 바꿨다.
- **JSON 폼 파싱 일원화**: `dialect_map`/`dialect_modes`의 `json.loads` + 예외 처리 + dict 여부 확인을 `_parse_json_object()` 하나로. 함수 안에 있던 `import json`도 모듈 상단으로 올렸다.

## 48. `dictionary.py` 모듈 분할 — 통신과 판정을 가른다 (2026-08-02)

## 49. 분할 검증 중 발견한 잠복 크래시 — 조사+보조 용언 분리 분기 (2026-08-02)

§46 분할이 정확도를 떨어뜨리지 않았는지 검증하다가, **분할 이전부터 있던** 버그를 하나 찾았다. 분할이 만든 것이 아니다(옛 커밋을 꺼내 같은 입력으로 재현해 확인).

- **증상**: `알고는있다`·`보고는싶다`처럼 **조사와 보조 용언을 붙여 쓴 줄**이 들어오면 `NameError: name 'to_restore' is not defined`로 터진다. 교정 요청 전체가 죽으므로, 원고에 그런 줄이 하나만 있어도 파일 전체가 교정되지 않는다(웹은 500, CLI는 트레이스백).

- **고친 내용**: 이 함수는 kiwi가 **넣자고 한** 공백을 다루므로, 조사+보조 용언 자리의 공백 삽입은 제47항 단서상 정답이다 — 되돌리지 않고 `continue`로 그대로 둔다. 바로 위 '안 되다' 분기와 같은 처리다. 반대 방향(붙이자는 제안)은 원래대로 `_protect_unfounded_joining()`이 막는다.
- **왜 테스트 276건이 못 잡았나**: 이 분기는 kiwi가 조사(J\*) 다음 보조 용언(VX) 사이에 공백을 **삽입**할 때만 열린다. 보통은 그 자리를 붙이자고 제안하므로(반대 방향) 실사용에서도 드물게만 열린다. 테스트 코퍼스·예제 자막 594줄에도 그런 줄이 없었다.
- **어떻게 찾았나**: `tools/check_names.py` — 모듈이 참조하는 전역 이름이 그 모듈에서 해석되는지 정적으로 확인한다. 실행 없이 이름 해석만으로 잡히는 부류다. 회귀 고정은 `tests/test_realusage_review.py::test_particle_before_auxiliary_split_is_kept`.

## 51. held-out 테스트셋 14건 → 41건 확대, 그 과정에서 방언 판정 버그 하나 (2026-08-03)

`docs/BACKLOG.md` 9번. 눈금자를 먼저 키우고 정확도 작업으로 넘어가기 위한 작업이다. 14건일 때는 한 건이 7.1%p라 개선과 노이즈가 구분되지 않았다. 41건이면 한 건이 2.4%p다.

- **라벨 검증 도구를 먼저 만들었다** — `tools/verify_eval_labels.py`. 낱말을 표준국어대사전·우리말샘으로 조회해 `표준`/`비표준`/`지역어·옛말`/`조회불가`로 찍고, `--file`로 "입력 표기 → gold 표기" 쌍을 받아 **왼쪽이 실제로 비표준이고 오른쪽이 실제로 표준인지**를 쌍 단위로 판정한다. gold가 틀린 평가셋은 엔진을 고치는 게 아니라 눈금자를 휘게 만드는 것이라 더 위험하다 — `.claude/skills/grammar-rule-verify-then-code`가 교정 규칙에 요구하는 "검증표 먼저"를 라벨에도 그대로 적용했다.
  - 이 도구를 만들며 **표준국어대사전은 비표준 표기도 표제어로 싣고 뜻풀이를 화살표 한 줄로만 적는다**는 것을 확인했다(`설겆-이` → `"→ 설거지."`). 우리말샘의 `"⇒규범 표기는 ~"`와 문구가 달라, 엔진 쪽 판정(`_opendict_item_is_standard`)만 쓰면 `설겆이`·`초콜렛`·`컨텐츠`가 전부 '표준'으로 찍힌다. 도구 안에 `_stdict_item_is_standard()`를 따로 뒀다.
- **후보 20쌍 중 15쌍만 통과**했고, 넣지 않은 5쌍은 이유와 함께 `examples/eval/candidates.txt`에 남겼다(다음 세션이 같은 조회를 반복하지 않도록). 대표적으로 `금새 → 금세`는 **'금새'도 표준국어대사전 표제어**(명사, 물건의 값)라 표기만으로 못 가른다 — 자동 교정 라벨 대신 반대 방향 함정(t09)으로 넣었다.
- **추가한 27건**: 외래어 자동교정 8, 맞춤법 자동교정 6, 과교정 함정 8(동음이의·조사·띄어쓰기), 의존명사 제안 플래그 2, 사투리 protect 3. 함정과 사투리를 늘린 이유는 이 엔진의 실패가 "못 고침"보다 **"고치면 안 되는 것을 고침"** 쪽에서 더 비싸기 때문이다.
- **확대 직후 결과: 36/41 = 87.8%** (직전 12/14 = 85.7%. 아래 수정 뒤 39/41 = 95.1%). 숫자보다 중요한 것은 **맞춤법 4/8**로 갈라진 것이다. 새로 드러난 미교정 3건은 `일찌기 → 일찍이`, `곰곰히 → 곰곰이`, `개거품 → 게거품`이며, 셋 다 사전 조회로 답이 확정되는 부류인데 지금 엔진이 손대지 못한다. 기존 실패 2건(`안절부절 → 안절부절못하다`, 사투리 assist 제안 플래그 없음)은 그대로다. → `docs/BACKLOG.md`에 새 항목으로 올렸다.

**부수 발견 — 방언 표제어가 붙임 근거로 새던 구멍(수정함)**: `깨끗히`·`움추리다`를 조회하다 `is_contemporary_general_word()`가 이 둘을 **현대 일반어(True)**로 판정하는 것을 봤다. 우리말샘은 방언·북한어·옛말 표시를 분야(`cat`)가 아니라 **어휘 구분(`type`)**에 넣는 항목이 있는데(`깨끗-히`: `cat=""`, `type="방언"`, 뜻풀이 `'깨끗이'의 방언`), 이 함수는 `cat`만 보고 있었다. 뜻풀이 문구 검사(`"지역에서는"`·`"지역어"` 등)도 `'X'의 방언`이라는 가장 흔한 형태를 잡지 못한다. 결과적으로 **방언 표제어 하나가 띄어쓰기 붙임의 근거로 통과**할 수 있었다 — 2026-07-31 커밋 `7a0966f`(역사·방언 표제어를 붙임 근거에서 제외)이 막으려던 바로 그 부류다. `type`도 같은 집합으로 검사하게 고쳤다(`subtitle_corrector/dictionary/headwords.py`). 고친 뒤 `깨끗히`·`움추리다` 모두 False, 일반어(`사랑`·`먹다`·`자동차`)는 True 유지. 전체 스위트 277건 통과.

**같은 날 이어서 — 드러난 미교정 3건을 고쳤다(39/41 = 95.1%)**. 세 건이 각각 다른 이유로 새고 있었다.

- **`일찌기 → 일찍이` (g17)**: 우리말샘이 `"규범 표기는 '일찍이'이다"`로 답을 이미 갖고 있었는데, `correct_nonstandard_terms()`가 **명사(NNG/NNP)만 조회**하고 있었다. 같은 성격의 명사 `눈쌀`·`설겆이`는 잡히면서 **부사(MAG)만 통째로 새던 것**이다. 태그 집합에 `MAG`를 넣었다. 넓히기 전에 코퍼스(테스트 문자열 + 예제 자막)의 부사 **90종을 전수 조회**해, 새로 바뀌는 것이 `일찌기 → 일찍이`와 `웬지 → 왠지` 둘뿐이고 **둘 다 정답**임을 확인했다 — 오탐 0건.
- **`곰곰히 → 곰곰이` (g18)**: 어느 사전에도 표제어가 없어(우리말샘 `⇒규범 표기는` 안내도, 표준국어대사전 `→` 안내도 없음) 동적 조회로는 닿지 않는다. 근거는 규정 쪽에 있다 — 한글 맞춤법 제51항 해설 "(5) 부사 뒤"에 `곰곰이`가 예시로 실려 있고, 온라인가나다도 같은 조항을 근거로 답했다(`qna_seq=306238`, 2026-08-03 WebFetch로 본문 확인). `ALWAYS_WRONG`에 근거와 함께 넣었다.
- **`개거품 → 게거품` (g19)**: `게거품`은 표준국어대사전 표제어, `개거품`은 두 사전 모두 없다. 다만 **kiwi가 `개`+`거품` 두 명사로 쪼개 읽어서** 낱말 단위 동적 조회에는 애초에 걸리지 않는다 — 사전에 답이 있었더라도 못 잡았을 자리다. 이것도 `ALWAYS_WRONG`.

**정적 목록을 늘린 것에 대한 정직한 정리**: `ALWAYS_WRONG`은 국립국어원 API로 닿지 않는 자리를 메우는 예외 통로다. 이번에 두 건을 보태며 각 항목에 **왜 동적 조회로 안 되는지**와 **어떤 근거로 정답을 확정했는지**를 주석으로 붙였다. 근거 없이 "흔한 오타라서" 넣기 시작하면 이 목록이 곧 확률적 추측 더미가 된다.

**남은 실패 2건**(고치지 않음, `docs/BACKLOG.md` 24번): `안절부절 → 안절부절못하다`(g05)와 사투리 assist 모드에서 제안 플래그가 나오지 않는 것(d04).

## 52. 사투리 표지 사전 전수 감사 — 27개 중 3개만 검증됨, 나머지 제거 + `to_standard` 자동 변환 차단 (2026-08-03)

평가셋 d04(사투리 assist에서 제안 플래그가 안 나옴)의 원인을 파다가 사투리 subsystem의 **데이터 자체**가 근거 없이 채워져 있는 것을 발견했다. d04 하나를 통과시키려고 표에 `빨리 → 퍼뜩`을 손으로 더 넣는 것은 같은 추측을 하나 더 쌓는 일이라, 표 전체를 사전으로 감사했다.

**감사 방법**: `DIALECT_TO_STANDARD`의 27개 항목을 전부 우리말샘으로 조회해, 방언 표제어로 등재돼 있는지와 뜻풀이가 표에 적힌 표준어와 맞는지 대조했다.

**결과 — 검증되는 것은 3개뿐**이었다.

| 부류 | 항목 |
|---|---|
| 한글이 아닌 쓰레기 | `기rab다`, `adio`, `monton`, `ありが다`, `phins`, ` Ấ리` |
| 뜻이 틀림 | `하르방→아버지`(실제 '할아버지'의 방언), `이까→이야`('오징어'의 방언), `모려→몰라`(표제어 뜻은 '계략'), `마르→배고프다`(화산 지형), `수다→것이다`(말수가 많음), `이우다→이르다`(⇒'이울다') |
| 표준어를 사투리로 등록 | `아주머니→아줌마`, `총각→청년`, `래→라고`, `거시기`(표준 대명사) |
| 우리말샘 미등재 | 12건(실제 사투리인데 사전에 없는 것도 섞여 있으나, 근거는 없다) |

**왜 심각한가 — 이 표는 텍스트를 실제로 바꾸는 경로였다.** `to_standard` 모드(웹 UI에서 고를 수 있었다)는 이 표로 문자열을 **단어 경계 없이** 치환한다. 실측:

```
'그래 노래를 불렀다'  ->  '그라고 노라고를 불렀다'   (전라도, to_standard)
'하르방이 왔다'       ->  '아버지이 왔다'            (제주도, to_standard)
```

자막 원고가 조용히 깨진다. 사투리 지정 화자의 기본값이 protect라 평소에는 안 닿지만, UI에서 한 번 고르면 바로 닿는 자리였다.

**조치**(사용자 결정: "검증 안 된 항목 전면 제거 + `to_standard` 차단")

- `DIALECT_TO_STANDARD`·`DIALECT_MARKERS`에서 사전으로 확인되지 않는 항목을 전부 지웠다. 남은 것은 `하르방 → 할아버지`(뜻 정정), `기냥 → 그냥` 둘뿐이다. 표가 이렇게 작은 이유와 되살리는 절차를 `dictionary/dialect.py` 상단 "사투리 표 감사" 주석에 남겼다.
- **`to_standard`는 더 이상 자동 변환하지 않는다** — 텍스트는 그대로 두고 제안 플래그만 만든다(`engine/dialect.py`, `engine/pipeline.py`). 표를 다시 채울 때 같은 사고가 재발하지 않도록 경로 자체를 내린 것이다. 웹 UI 문구도 "표준어로 바꾸기 제안 (자동 변환 아님)"으로 고쳤다.

## 53. '명사 + 명사 + 하다'를 붙여 버리던 과교정 — 붙임 차단 + 반대 방향은 플래그 (2026-08-03)

사용자 보고: `나물 타령하셨어`는 `뭔 생각 하냐`와 같은 구성이므로 `나물 타령 하셨어`로 띄어 써야 한다.

**확인한 실제 동작 — 양방향으로 틀렸다.**

```
'나물 타령 하셨어'  ->  '나물 타령하셨어'    (맞게 띄어 놓은 것을 붙여 버림)
'나물 타령하셨어'   ->  그대로               (아무 말도 안 함)
'뭔 생각하냐'      ->  '뭔 생각 하냐'        (관형사가 앞에 오면 정상)
```

원인은 두 함수가 **관형사(MM)·관형형(ETM)만** 관형어로 인정한 것이다. `나물`은 명사(NNG)라 `correct_adnominal_noun_verb_split()`의 분리 대상도 아니고, `correct_action_noun_affix()`의 붙임 예외에도 걸리지 않았다.

**규범 근거 확인**(코드보다 먼저 — `.claude/skills/grammar-rule-verify-then-code`)

- 온라인가나다 `qna_seq=320467`(2025-09-11): "행위성이 있는 명사 뒤에서는 접사 '-하다'를 붙여 쓸 수 있습니다. … `순간 이동을 하다`처럼 **구 구성이면 띄어 씁니다**"(`순간 이동 하다`·`나눠 주기 하다`를 띄어 쓰는 예로 들었다).
- 같은 게시판의 `수학 공부 하다` 문의 답변: "`수학`이 `공부`를 수식하여 명사구를 만든 것으로 본다면 **띄어 쓰는 것이 바르다**. **다만** `수학을 공부하다`처럼 조사 `을`이 생략된 목적어로 이해할 수도 있다."

즉 **띄어 쓴 표기는 확실히 맞고, 붙여 쓴 표기도 해석에 따라 가능**하다. 그래서 방향을 갈라 처리했다.

- **붙이지 않는다(자동 교정 차단)**: `correct_action_noun_affix()`에서 앞말이 명사(NNG/NNP)이고 공백 하나로 붙어 있으면 붙임을 건너뛴다. 맞는 표기를 깨뜨리는 것이 가장 나쁜 실패이므로 이쪽은 확실히 막았다.
- **나누지는 않는다(플래그)**: 새 함수 `check_noun_phrase_affix_spacing()`이 `나물 타령하셨어`에 `나물 타령 하셨어`를 제안하고, 두 해석이 모두 가능하다는 사실을 이유에 적어 사람이 판단하게 한다. 관형사·관형형이 앞에 오는 경우는 해석이 하나뿐이라 예전처럼 자동으로 나눈다.
- **kiwi 태그 불안정 대응**: `어제 청소 했다`의 `어제`는 시간 부사어인데 kiwi가 붙여 쓴 문장에서는 NNG로, 띄어 쓴 문장에서는 MAG로 태깅한다. 그대로 두면 `어제 청소했다`를 나누자고 플래그하는 오탐이 생긴다. 그래서 `_has_adverb_reading()`으로 **kiwi 자신의 대안 분석**에 부사 읽기가 있으면 플래그하지 않는다(`_has_determiner_reading`과 같은 방식 — 확률적 추측이 아니라 "다른 읽기가 존재한다"는 사실을 근거로 쓴다).

**대가(기록해 둔다)**: 앞 명사가 관형어가 아니면서 부사 읽기도 없는 경우, 정당한 붙임을 놓친다(`생일 선물 받았어`는 이제 붙이지 않는다). 표면만으로 관형어인지 목적어인지 가릴 수 없으므로 맞는 표기를 지키는 쪽을 택했다.

회귀 고정: `tests/test_realusage_review.py`에 2건(붙임 차단 4개 입력, 플래그 방향 2개 입력).

## 54. 실사용 감수 6차 — 사용자 보고 7건 (2026-08-03)

한 세션에서 사용자가 실제 자막을 돌려 보며 보고한 것들이다. 절반이 **이 프로젝트가 스스로 만든 규칙의 오탐**이었고, 그중 하나는 같은 날 §53에서 내가 넣은 것이다.

**① '감사합니다'를 '감사 합니다'로 플래그 — §53의 플래그를 제거했다**

`소중한 시간 감사합니다`에 "'시간 감사'가 명사구라면…"이라는 이유로 분리 후보를 냈다. 이유 자체가 말이 되지 않는다 — `시간 감사`는 명사구가 아니고 `감사하다`는 한 단어다. **사전으로 두 경우를 가릴 수 없다**는 것이 문제의 핵심이다: `타령하다`도 `감사하다`도 표준국어대사전 표제어라 근거가 같다. 앞 명사가 관형어인지(나물 타령) 아닌지(시간 감사)는 표면에 없다. 그래서 분리 제안 쪽은 통째로 지웠다. **붙임 차단(`나물 타령 하셨어`를 붙이지 않는 것)은 유지한다** — 그쪽은 원문을 지키는 방향이라 판정이 틀려도 손해가 없다.

**② '그건 내 잘못이 아냐'가 '그건 내 잘못이, 아냐'로 잘림**

`아냐`(='아니야'의 준말, 서술어)를 kiwi가 감탄사(IC)로 태깅해 "문장 끝 감탄사 앞 쉼표" 규칙이 걸렸다. **조사 뒤는 서술어나 체언이 오는 자리**이므로 그 자리의 IC는 오분석으로 본다(보격 조사 `이` 뒤라면 '아니다/되다'가 와야 한다는 것이 규정상 확실하다). 부수로 `네 책임이 아냐`도 고쳤다 — `네`(=너+의)가 IC로 태깅돼 문장 앞 쉼표가 들어갔다. kiwi 대안 분석에 대명사+관형격 조사(NP+JKG) 읽기가 있으면 관형어로 보고 쉼표를 넣지 않는다(`_has_determiner_reading` 확장, '그 빌리지' 건과 같은 방식).

**③ '아냐'를 '아니야'로 — 확인 플래그(사용자 결정)**

둘 다 표준이다(표준국어대사전 `아냐` = "'아니야'의 준말"). 표준어끼리의 치환은 이 프로젝트가 막는 부류라(평가셋 t12) 자동 교정하지 않고 본말 후보만 남긴다. 새 목록 `_CONTRACTIONS_TO_FULL_FORM`은 항목마다 사전 근거를 적는 조건으로 늘린다.

**④ 성명 뒤 '님'·'씨' 띄어쓰기**

근거: 표준국어대사전 `님`(의존 명사) "그 사람을 높여 이르는 말. '씨'보다 높임의 뜻을 나타낸다.", 온라인가나다 — "그 사람을 높이거나 대접하여 부르거나 이르는 말로 쓸 때는 의존 명사이므로 앞말과 띄어 쓴다(`김 씨`·`길동 씨`·`홍길동 씨`). 성씨 자체·가문을 뜻하면 접미사라 붙여 쓴다(`김해 김씨`)."

kiwi가 이 둘을 앞말 태그로 갈라 준다 — 사람 이름은 NNP(`홍길동님`), 직위·관계는 NNG(`사장님`·`고객님`·`달님`). **앞말이 두 글자 이상 고유명사일 때만 자동 교정**하고, 한 글자 고유명사(성 한 글자)는 `김씨`(가문)와 `김 씨`(그 사람)가 표기만으로 갈리지 않아 플래그만 남긴다.

**⑤ 접두사 '처-'를 '쳐'로 적은 것**

검증표(표준국어대사전): `처-먹다`("'먹다'를 속되게 이르는 말")·`처-넣다`("마구 집어넣다")·`처-박다`·`처-마시다`·`처-지르다`는 등재, `쳐먹다`류는 미등재. 반대로 `쳐다보다`·`쳐들다`·`쳐들어가다`는 쳐-형 자체가 표제어다. 그래서 규칙은 정적 목록이 아니라 **조회**로 만들었다 — 붙임형(처X)이 표제어이고 쳐X는 아닐 때만 다룬다. `쳐바르다`는 둘 다 미등재라 손대지 않는다.

자동 교정은 **뒤가 본용언(VV)일 때만** 한다(`쳐먹어라`·`쳐 먹어라` -> `처먹어라`). 보조 용언(VX) 자리는 `치다`의 활용과 구분되지 않는다 — `박수를 쳐 줘`는 정상인데 `처주다`도 표제어라 조회 조건만으로는 걸러지지 않는다. 사용자가 보고한 `쳐 하든가`가 이 자리다: `처하다`는 표제어이지만 뜻이 **處하다**(처지에 놓이다)여서 접두사 '처-'의 뜻이 아니다. 그래서 자동으로 바꾸지 않고 근거와 함께 플래그한다. 이 자리에서 띄어쓰기 검사가 `쳐하든가`(쳐 그대로 붙임)를 함께 제안해 서로 어긋나는 제안 두 개가 남던 것도 막았다(`_protect_cheo_prefix_gap`).

**⑥ 구두점 앞 공백 — 문맥 무관 규칙으로 못 박았다**

"마침표, 물음표, 느낌표, 따옴표 모두 띄어쓰기 없이 사용한다"(사용자 지정). `지랄!`을 `지랄 !`로 제안하던 것을 판정 없이 막는다(`_strip_space_before_punctuation`, 닫는 부호 계열만 대상 — 여는 따옴표·괄호 앞 공백은 정상이다).

**⑦ `[]`·`()` 뒤 한 칸 — 설정과 무관하게 적용**

전에는 **설정한 부호만** 표시로 봤다. 그래서 소괄호를 쓰는 원고에서 `(민수)안녕하세요`에 아무 일도 하지 않았다. "[] 이나 () 뒤에 말자막이 오는 경우에는 띄어쓰기가 필요하다"는 규칙이므로 두 부호를 기본 표시로 넣었다(설정 부호는 그 위에 더한다). 낡은 테스트 2건("설정 안 한 부호는 건드리지 않는다")을 새 규칙에 맞게 고쳤다.

**부수 발견 — 닫는 따옴표 앞의 줄 끝 마침표**: 사용자가 준 `"지영아, 나는 너를 좋아해. "`가 `좋아해, "`로 바뀌었다. 마침표 뒤에 공백과 따옴표가 있어 "문장이 이어진다"고 본 탓이다. 닫는 부호만 남은 경우는 줄 끝으로 보고 마침표를 지우고 따옴표를 붙인다(`"지영아, 나는 너를 좋아해"`).

**⑧ 미등록어 플래그에 표기 후보 추가**

`에베레스트 트레커`에서 "사전에 없는 단어: 트레커"로 끝나 무엇과 비교해야 하는지 알 수 없었다. 이제 **표기 변이형을 사전에 물어봐서** 근거가 있으면 후보로 적는다 — `'트레커'는 '트래커'일 가능성이 있습니다(사전 근거 있음)`. 변이는 외래어 표기에서 가장 흔히 갈리는 모음 짝(ㅐ↔ㅔ, ㅒ↔ㅖ) 한 자리 치환만 만들고, 후보는 단독 표제어·국립국어원 표제어의 구성 요소(`트래커`는 `지피에스^트래커`로 등재)·kornorms 용례 중 하나에 걸려야 남는다. 뜻을 추측하는 것이 아니라 표기를 조회하는 것이라 원칙과 충돌하지 않는다. 후보가 하나뿐이면 `suggested_fix`도 채우지만 자동 교정은 하지 않는다 — 어느 쪽이 맞는지는 원어 발음이 정한다.

**⑨ 같은 세션 추가 보고 3건 (2026-08-03)**

- **`참나` vs `참, 나`** — 온라인가나다는 "'참나'가 사전에 실려 있지 않은데, 이를 띄어 쓸 근거도 분명하지 않습니다. … 하나의 감탄사로 쓰인다면 앞으로 사전에 실릴 수도 있다"고만 답했다. 사용자 결정: **감탄사 `참나`(기가 막히고 어이없다)는 붙여 쓴다.** 다만 `참`은 '그런데/생각났는데'의 뜻으로도 쓰여(`참, 나 결혼해`) 표기만으로 갈리지 않는다. 그래서 ① 띄어 쓴 `참 나` 사이에 쉼표를 넣지 않고(예전에는 `참, 나 어이없네`로 바꿨다) ② 두 읽기를 나란히 적은 플래그만 남긴다. **자동 적용 후보(`suggested_fix`)를 일부러 비운다** — 하나를 후보로 내놓으면 리포트 적용 기능이 그쪽으로 굳히기 때문이다(사용자 지정: "헷갈린다면 자동교정하지 말고 플래깅할 것").
- **`처맞고`를 `처 맞고`로 가르던 제안** — `처-`는 접두사이므로 뒤 용언에 붙여 쓴다. 파생어가 사전에 없어도(`처맞다` 미등재) 띄어 쓸 근거는 없는데, kiwi가 이 `처`를 명사(NNG)로 읽어 가르자고 제안했다. `_protect_cheo_prefix_split()`으로 막았다.
- **`쳐맞고`** — `처맞다`·`쳐맞다` 둘 다 미등재라 사전으로 정답을 확정할 수 없다. 자동 교정하지 않고 `처맞고`를 후보로 알린다(`check_undocumented_cheo_derivative`). 사전 근거가 있는 `쳐먹다`류(⑤)와 달리 이쪽은 접두사 원칙만 근거라 세기를 낮춘 것이다.

**서버 재시작 주의**: 사용자가 `둘레길 산책하던 사람`에서 이미 지운 플래그(§54 ①)를 다시 봤다. `--reload` 없이 띄운 uvicorn이 옛 코드를 물고 있었기 때문이다. **웹으로 확인을 부탁할 때는 서버를 다시 띄우거나 `--reload`로 띄울 것.**

## 55. 원문 왜곡 추적 — 인제스트 보장, 실사용 원고 전수 대조, 조용한 장애 표시 (2026-08-03~04)

사용자 보고: "실제 srt 파일을 올리면 원문의 띄어쓰기가 왜곡되어 교정에 들어간다. 원문을 교정하지 말라는 뜻이 아니다 — **사용자가 업로드한 원문 그대로를 가져와 교정해야 한다.**" 처음에는 교정 규칙 문제로 읽었으나, 파고들자 세 층에서 각각 문제가 있었다.

### 1층 — 파일을 읽는 경로 (`decoding.py` 신규)

- 모든 파서가 `read_text(encoding="utf-8-sig")` 하드코딩이었다. **국내 자막에 흔한 cp949(EUC-KR) 파일은 그 자리에서 `UnicodeDecodeError`로 죽었다.**
- 인코딩 판정을 한곳에 모았다: BOM이 있으면 BOM을 따르고(파일이 스스로 밝힌 것이라 추측이 아니다), 없으면 UTF-8 → cp949 → euc-kr 순으로 **엄격히** 시도한다. 어느 것으로도 못 읽으면 글자를 추측해 채우지 않고 실패한다 — 깨진 글자로 교정하는 것보다 실패가 낫다.
- **개행 정규화를 빼먹어 사고를 재현했다**: `read_text`는 CRLF를 LF로 바꿔 주는데 `read_bytes`로 바꾸면 그게 사라진다. 그대로 두면 `split("\n\n")`이 먹지 않아 **파일 전체가 자막 한 항목으로 뭉친다**(타임코드까지 대사에 섞임). 사용자가 준 파일 4개가 전부 CRLF였다.
- **`verify_ingest_fidelity()`**: 읽어 낸 각 대사가 원문의 부분 문자열인지 매 업로드마다 확인한다. 파싱은 구조를 잘라내는 일이지 글자를 바꾸는 일이 아니므로 형식·인코딩과 무관하게 성립해야 하는 조건이다. 어긋나면 **교정을 진행하지 않고** 422로 알린다.

### 2층 — 설명되지 않는 변경을 막는 관문 (`edit_guard.py` 신규)

개별 규칙을 고치는 방식으로는 끝나지 않는다(새 규칙마다 같은 부류가 다시 생긴다). 규칙이 한 줄을 고칠 때마다 검사한다: 글자 뼈대(공백·문장부호 제외)가 그대로면 통과, 바뀌었으면 **그 규칙이 남긴 로그로 원문을 재구성**해 같은지 본다. 설명되지 않으면 그 규칙의 결과를 버리고 원문을 유지한다(fail-closed). 사투리 표 사고(§52 `노래` → `노라고`)는 규칙을 고치지 않아도 이 검사만으로 막힌다.

조사 이형태(`로보트를` → `로봇을`)는 규칙 로그에 낱말 치환만 남으므로 비교에서 한쪽으로 모은다 — 이 보정을 빼면 정당한 교정이 막힌다(평가셋 g01에서 즉시 확인).

**막지 못하는 것**: 근거는 있으나 문맥상 틀린 교정(동형이의어를 사전 근거로 바꾸는 경우)은 통과한다. 그건 왜곡이 아니라 오교정이며, 아래 3층이 그 부류다.

### 3층 — 실제 원고 전수 대조로 드러난 과교정 9건

### 부수 — 조용한 장애를 드러냈다

## 56. 6강 원고 대조 — 합성어 자동 병합을 제안으로 강등, 보조 용언은 2단계 선택을 따른다 (2026-08-04)

§55에 이어 6강 과제 자막(483항목)을 전수 대조했다. 변경 10건 중 보조 용언 3건은 사용자가 고른 기준(원칙)대로 동작한 것이고 `발달 된 → 발달된`·`입학 될까요 → 입학될까요`는 정당한 파생어 붙임이다. 남은 두 건이 같은 뿌리였다.

```
'남의 집 개는 시끄럽다고'  ->  '남의 집개는'      집개 = 집에서 기르는 개
'따지러 온 다음 날'       ->  '다음날'           다음날 = 정하여지지 아니한 미래의 어떤 날
```

**사전으로는 가를 수 없다.** `집개`·`다음날`·`개새끼`·`노천카페` 넷 다 표준국어대사전 표제어이고 준말·비유 표지도 없다. 앞의 둘은 붙이면 뜻이 바뀌고 뒤의 둘은 타당한데, 그 차이는 문맥에만 있다.

**결정(사용자): 자동 병합을 제안으로 강등한다.** 붙임형이 표제어라는 것은 "붙여 쓸 수도 있다"는 근거이지 **원문이 띄어 쓴 것이 틀렸다는 근거가 아니다.** `correct_compound_spacing()`은 후보만 모으고 새 `check_compound_merge_candidate()`가 확인 항목으로 낸다. 반대 방향(붙여 쓴 것을 사전 근거로 띄우기)은 그대로 자동이다 — 그쪽은 "사전에 그런 낱말이 없다"는 부정 근거라 성격이 다르다.

이 결정으로 `예산 안에서 → 예산안에서`(§55에서 위치 명사 가드로 막은 것)도 이중으로 막히고, 앞으로 같은 부류가 새로 생기지 않는다. 테스트 7건이 옛 계약(자동 병합)을 고정하고 있어 함께 고쳤다.

**보조 용언 기본값 — 되돌렸다.** 처음에는 말줄임표와 같은 논리로 기본값을 원문 유지로 바꿨으나, 사용자가 "보조 용언 기본값은 원문 유지가 아니라 **사용자가 2단계에서 지정한 대로** 해야 한다"고 정정했다. 화면 2단계의 '띄어쓰기 기준'이 원칙으로 미리 선택돼 있으므로 엔진·API 기본값도 원칙으로 되돌렸다. `keep`(원문 유지)은 선택지로 남아 있고 명시적으로 골랐을 때만 적용된다. 혼용 감지는 새로 넣은 `check_aux_verb_consistency()`가 문서 단위로 알린다(제47항은 둘 다 인정하지만 한 문서에서 섞이면 오류다).

**검증**: 전체 311건 통과, held-out 40/41 = 97.6%, `tools/check_names.py` 0건.

## 57. 7강 원고 대조 — 등장인물 이름이 바뀌던 사고 (2026-08-04)

7강 과제 자막(645항목) 전수 대조. 변경 8건 중 3건이 오교정이었고, 첫 건이 가장 심각했다.

**① `세상에, 러스` → `세상에, 루스` (123번) — 등장인물 이름을 바꿨다**

원인이 두 겹이다.

- kornorms 외래어 표기 용례에 `Ruth, Babe`와 `Luce, Henry Robinson`의 **오표기 목록**으로 `러스(X)`가 등재돼 있다. 둘 다 `루스`를 가리키므로 `loanword_fix()`의 "정답이 하나로 일치하면 자동 반영" 조건을 통과했다. 실제 원고의 인물은 Russ다 — **사람 이름의 정답은 원어를 알아야 갈리는데 텍스트만으로는 알 수 없다.**
- 고유명사는 자동 반영하지 않고 플래그만 하는 규칙이 이미 있었으나, kiwi가 이 줄에서 `러스`를 일반명사(NNG)로 태깅해 뚫렸다. 같은 이름을 `세상에, 러스` 한 줄만 넣으면 NNP로 잡는다 — **1순위 태그는 문장에 따라 흔들린다.**

조치: ⓐ kornorms 용례가 **인명·지명 분류(`foreign_gubun`)뿐일 때는 자동 반영하지 않는다**(일반 용어는 원어가 갈릴 일이 없어 그대로 자동 — `초코렛` → `초콜릿`, `리모콘` → `리모컨` 유지). ⓑ 대안 분석에 고유명사 읽기가 하나라도 있으면 고유명사로 본다.

**② `내 탓 하지 마` → `내 탓하지 마` (147번)**

`내`를 kiwi가 `나`(NP)+`의`(JKG)로 읽어, 관형어 뒤 접사 붙임을 막는 가드(`MM`/`ETM`)에 걸리지 않았다. **관형격 조사도 관형어를 만든다** — 조건에 `JKG`를 넣었다.

**③ `빌어먹을 차 안 세우면` → `빌어먹을, 차 안 세우면` (374번)**

`빌어먹을`은 감탄사(욕)로도, `빌어먹다`의 관형사형(그 망할)으로도 읽힌다. 사용자 판정: **둘 다 가능하므로 플래그로 내고 사람이 고른다.** 대안 분석이 두 토큰(`빌어먹`+`을`)이라 같은 길이 한 토큰만 보던 기존 가드(`_has_content_word_reading`)로는 못 잡았다 — 토큰 구간이 관형사형 어미로 정확히 끝나는 후보를 보는 `_has_adnominal_phrase_reading()`을 추가했다.
