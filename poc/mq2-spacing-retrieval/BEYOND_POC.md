## ① 여러 모델을 하나의 파이프라인으로

영상 하나를 넣으면 자막이 나온다. **모델 셋과 규칙 엔진 하나가 한 줄로 이어져 있다.**

```
영상 + 원어 스크립트
   │
   ├─ 전사        Whisper (ffmpeg 9.0 내장 필터, ggml-large-v3-turbo)
   │                 checker/transcribe.py
   ├─ 말소리 구간   Silero VAD (2MB ONNX)
   │                 checker/vad.py — 음량이 아니라 소리의 모양을 본다
   ├─ 대조        원어 스크립트와 전사 정렬
   │                 checker/align.py
   ├─ 번역 1차     EXAONE 3.5 7.8B (로컬 Ollama)
   │                 checker/translate.py — 오역 없이 빠르게
   ├─ 번역 2·3차   EXAONE 3.5 (같은 모델, 다른 지시)
   │                 checker/revise.py — 2차 용어·맥락 / 3차 말투·흐름
   ├─ 한국어 교정   규칙 + 국립국어원 API 6종
   │                 checker/korean.py → korean-subtitle-corrector
   ├─ 재분할       한국어 기준으로 줄을 다시 끊는다
   │                 checker/resplit.py
   └─ 스포팅       타임코드 확정 + 규정 검사 51종
                     checker/timing.py, checker/checks.py
```

**실측**: 20초 영상이 전사·번역·재분할·스포팅까지 **8초** (커밋 `a6a6dfb`, 2026-08-11)

> **2026-08-12 갱신 — 이 파이프라인의 단계 경계가 정리됐다.** 이 PoC와는 별개 작업이고
> MQ2 범위가 아니지만, 위 설명이 사실과 달라지므로 적어 둔다.
>
> 오케스트레이션이 세 곳(`cli.py`·`app/jobs.py`·`plugin.py`)에 흩어져 있어 **입구마다
> 단계 순서가 달랐다** — 같은 자막에 같은 설정을 줘도 SE 플러그인과 GUI가 다른 리포트를
> 냈다. `checker/pipeline.py`로 모아 순서를 하나로 정했다(한국어 교정 → 규정 자동교정 →
> 규정 검사). 그 과정에서 **GUI와 CLI가 한국어 교정 결과를 받아 놓고 버리고 있던 것**도
> 드러나 고쳤다 — 화면에 한국어 확인 항목이 한 건도 뜨지 않고 있었다.
>
> **2026-08-14 검증 — 끝났다.** 네 입구(CLI·GUI·SE5 플러그인·SE4 플러그인)가 모두
> `pipeline`을 지난다. SE4 쪽은 C# DLL이라 직접 부르지 않고 `checker/cli.py`를 실행한다.
> 단계는 셋에서 **여덟**(소재·번역 3단·한국어 2단·조사 2종)으로 늘었고, `STAGES` 선언과
> `stage_` 함수의 대응을 시험이 고정한다. 테스트 758건 통과.

### 왜 번역을 세 번 돌리나 — 사람이 하는 순서 그대로

커밋 `d4f2727`("번역을 1차·2차·3차로 나눠 돌린다"). 작업자 교육자료가 단계를 이렇게
나누고, 그것을 그대로 옮겼다.

    1차   오역 없이 빠르게. 맥락 생각 말고
    2차   올바른 한국어로. 전문 용어 조사, 맥락 안에서 문장의 역할 바로잡기
    3차   영상 없이 줄글로 읽으며 말투·흐름 윤문

    (ex.) 1차  그들과 싸우기 전에 그들을 발견해야 한다
          2차  놈들과 싸우기 전에 우선 찾아야 한다
          3차  우선 찾아야 싸우든 말든 하지

**한 번에 다 시키지 않는 이유**: 한 번에 "잘 번역해라"라고 하면 모델이 세 가지를
뒤섞어 어중간하게 낸다. 1차는 정확도, 2차는 용어와 맥락, 3차는 말맛 — 볼 것이 다르다.

### 오늘의 PoC와 어떻게 이어지는가

MQ2의 결론은 **"맞춤법·띄어쓰기에는 AI를 쓰지 말고, 정답이 하나가 아닌 곳에 쓰라"**
였다. 위 파이프라인이 그 경계를 그대로 구현하고 있다 — 번역·윤문은 EXAONE이, 교정은
규칙 엔진이 한다. 오늘의 PoC는 그 경계가 옳았음을 데이터로 확인한 것이다.

## ② 파인튜닝 · 하이퍼파라미터

**파인튜닝은 하지 않았다.** 그러나 모델과 설정은 감으로 고르지 않았다.

### 모델 선택 실측

| 자리 | 후보 | 실측 | 고른 것 |
|---|---|---|---|
| 전사 | `ggml-base` (141MB, CPU) | 7.8배속 · `그 석태들 기본강에서` | |
| | `ggml-large-v3-turbo` (1.5GB, GPU) | **23.1배속** · `그 서프트웨어 기본강의에서` | ✔ |
| 번역 | `qwen2.5:7b-instruct` | 28.4초 · `thermostat`→**저수온계**(오역) · 존댓말/반말이 줄마다 뒤집힘 | |
| | `exaone3.5:7.8b` | **6.1초** · `thermostat`→온도 조절기 · 말투 일관 | ✔ |

같은 60초 구간, RTX 3060 Ti. 출처: `checker/transcribe.py` 서두, 커밋 `a6a6dfb`.

**큰 모델이 더 빨랐다** — GPU가 붙기 때문이다. 품질을 낮출 이유가 없었다.
한국어 특화 모델이 4.6배 빠르고 더 정확했다.

> 오늘의 PoC에서 같은 두 모델을 **띄어쓰기 판정**에 다시 재 봤더니 순서가 뒤집혔다
> (EXAONE 89.1% vs Qwen 76.1%는 유지되지만, 둘 다 신경망을 안 쓰는 방법 82.6%에
> 못 미치거나 라이선스가 막힌다). **같은 모델이 작업에 따라 다르게 쓸모 있다**는 것이
> 두 측정을 나란히 놓으면 보인다.

### 설정 실측

| 설정 | 값 | 왜 |
|---|---|---|
| 번역 묶음 `batch` | 12 | 한 줄씩 보내면 빠르지만 대명사·말투가 자막마다 흔들린다 |
| 앞 문맥 `context` | 3 | 이미 옮긴 앞줄을 보여 주고 이어지는 대사로 쓰게 한다 |
| 전사 `max_len` | **쓰지 않음** | 전사 단계에서 글자 수를 자르면 문장이 부서진 채로 굳는다. 재단은 뒤에서 |
| 온도 `temperature` | 0 | 교정·번역은 창작이 아니다. 같은 원고를 두 번 돌려 다르면 신뢰할 수 없다 |
| 뜻풀이 가드 문턱값 | 0.02 | 오늘의 PoC. 낮추면 놓치고 높이면 정당한 붙임까지 되돌린다 |

### 파인튜닝을 안 한 이유, 그리고 준비해 둔 것

짝지어진 학습 데이터 `(틀린 표기, 고친 표기, 사람의 판정)`가 없다. 규정 문서와
평가셋으로는 그 짝을 만들 수 없다.

그래서 **데이터를 모으는 장치를 본체에 붙여 뒀다** —
`subtitle_corrector/feedback.py`(2026-08-12, 기본 꺼짐). 화면에서 제안을 채택하거나
넘길 때마다 그 판정을 JSONL로 쌓는다. 원고 전문은 해시로만 남기고 줄 단위 텍스트만
저장한다. 몇 천 건 쌓이면 그때 파인튜닝을 검토할 일이다.

## ③ 배포

**웹 데모는 없다.** 대신 두 가지가 있다.

| | 내용 |
|---|---|
| **실행 파일** | `.exe`로 빌드한다 — 파이썬 없이 돌아간다 (커밋 `7dbf3dd`, `자막편집기.spec`). GUI(`app/window.py`), 파형 편집(`d5630c9`), 단축키·화면 배치(`153f2df`)까지 들어 있다 |
| **웹 API** | 교정기는 FastAPI + `static/index.html`로 브라우저에서 파일을 올려 쓴다. Supabase 연동으로 결과를 저장·재조회한다 |
| **SE 플러그인** | SubtitleEdit 4에 붙는 C# 플러그인(`plugin/se4/`) — 기존 작업 환경 안에서 쓴다 |

### 오늘의 PoC를 배포하지 않은 이유

퀘스트 필수 항목이 아니고, 세 가지가 실제로 막는다.

1. **국립국어원 API 키는 개인 발급**이다. 공개 데모에 올리면 쿼터가 고갈된다 —
   교정기가 이미 업로드 크기를 1MB로 제한한 이유가 그것이다
2. **임베딩 모델 500MB**를 무료 티어 512MB에 올릴 수 없다. kiwipiepy(310MB)만으로도
   이미 한계에 걸린 기록이 있다(`docs/KNOWN_LIMITATIONS.md`)
3. 결론이 **"만들지 않는다"**라 배포할 물건 자체가 없다

시연은 [`README.md`](README.md) §6과 `demo_output*.txt`로 갈음했다.

>   지금 구조가 이미 `.env`의 키를 쓰므로 그대로 간다
> - 절대 하면 안 되는 것: 사전 데이터를 내려받아 제품에 동봉하는 것

## 정리 — 오늘 한 것과 이미 있던 것

| | |
|---|---|
| **2026-08-12 (오늘, MQ2)** | 문제 정의서 · 평가셋 76건 · arm 7종 · 실험 2회 · 사례집 50건 · 감사 도구 · 결론 |
| **그 전에 이미 있던 것** | 다중 모델 파이프라인 · 모델 선택 실측 · `.exe`/웹 API/SE 플러그인 · 감수 로그 1,900줄 · 테스트 444건 · 상용화 확인 목록 |

오늘의 PoC는 새 시스템을 만든 것이 아니라, **이미 돌아가는 시스템에 AI를 하나 더
얹어도 되는지 물어본 것**이다. 답은 "이 자리에는 얹지 마라"였고, 그 판단의 근거가
이 폴더에 있다.
